# 字体库功能规划（已确认使用方式）

后续开发已依据《字体库产品设计与开发文档》展开。目标是把字体设计的成品图、生成提示词和参考素材整理为可复用的字体卡片，通过“选案例 → 整组资料填入对话 → 自行修改 → 生成 → 收藏结果”完成闭环。

用户已确认：字体库全局共用，所有项目均可引用；“一键参考”默认把字体成品图、原提示词和原参考图全部填入当前对话，由用户自行修改后生成。这里的字体资产与生成结果均为字体设计图片。

## 1. 页面与组织

最左侧增加“字体”，放在画布、提示词附近。进入字体库后保留平台现有整体风格，不增加多级导航。

页面包含：标题、搜索、上传图片、从历史导入；下方是“全部 / 收藏 / 最近使用 / 一级分组”筛选和卡片网格。分组支持新建、改名、移动、删除；删除分组时卡片归入未分组。可选少量自由标签，不预设大量必填分类。

卡片以字体图为主，使用完整显示而非裁掉文字；显示名称、示例文字、分组。主按钮“一键参考”，次操作放在更多菜单。支持大图预览与收藏。透明图片采用棋盘底或浅/深底预览，便于查看黑色、白色字形。

点卡片打开右侧详情抽屉，展示：成品图、示例文字、可复用风格描述、原始提示词、原参考图（保留顺序）、生成参数和来源。复杂信息默认折叠，网格不显示长提示词。

## 2. 两条收录路径

### 上传自己的设计图片

拖入或选择 JPG/PNG/WebP，支持批量；默认一张一张建卡片，可批量设分组。只需图片和名称即可保存；名称可由文件名预填。示例文字、风格描述、提示词和参考图均可后补。

上传图片默认作为字体风格样本，不误认为“这张图当时使用的参考图”。原提示词未知就保持未知。提供可选“识别文字 / 分析风格”，经用户启动后使用已配置的视觉模型，产出建议并允许修改；识别结果不能写成原始提示词或覆盖已有资料。失败不影响上传收录。

### 从现有作品收藏

画布图片右键、对话生成图菜单增加“收藏到字体库”；字体库支持“从历史导入”，按项目、时间和关键词查找并多选，复用现有历史记录接口，无需恢复全局图库导航。

自动整理能明确对应的内容：

- 成品图原文件及缩略图。
- 当次实际生成提示词，另存原用户输入（能找到时）。
- 当次有顺序的参考图片及各自角色/说明（能找到时）。
- 模型、比例或像素尺寸、质量、输出格式、背景等实际记录的参数。
- 来源项目、图片记录、聊天/任务关联 ID、生成时间。

历史参数缺失应显示“未记录”，参考文件失效应显示“缺失，可补图”，不得猜测并伪装为原记录。匹配优先使用明确的 ID；时间相近或文本相同只作为候选，不能静默关联其他任务。新生成任务补齐 recipe 快照，保证以后能准确追溯。

收录弹窗仅需确认名称、示例文字、分组；有缺项可直接保存后补。重复收录同一作品提示已存在，允许打开原卡片。

## 3. 一键参考：整组资料填入对话（已确认）

默认流程：

1. 点卡片的“一键参考”，返回当前项目画布并展开对话输入区，不跳到案例的来源项目。
2. 将原提示词作为可编辑文本填入，同时带入字体成品图及原参考图。
3. 成品图标为“字体样式”，原参考图按原顺序显示，保留其原有引用含义。引用卡片可逐张移除、调整顺序或补充其他图片。
4. 用户直接在现有输入框修改目标文字、风格和其他要求；不强制填写单独的“新文字”表单。
5. 点击现有“发送/生成”后进入当前后台队列，结果保存在当前项目画布和对话。
6. 满意的结果可手动“收藏到字体库”，保存为新卡片并关联来源卡片。不会自动收录所有结果。

“一键参考”仅准备输入，不自动发送或启动生图。

### 输入内容和引用的处理

- 输入框为空：直接填入原提示词、成品图和原参考图。
- 输入框已有草稿：默认追加为一个清楚分隔的案例段落，原有文字与引用保留；提供“替换输入”次操作，替换前保存原草稿，并支持“撤销套用”。
- 图像显示角色清楚区分“字体样式”和“原参考图”。提示词有图1/图2等引用时，按引用身份重建映射，保持其语义，不因新增成品图而指错图片。原始提示词在卡片中保持原样，输入副本可以更新引用标记。
- 去重时保留引用角色，同一文件承担两个角色时不能直接丢掉一个角色。原参考图之间的顺序保持不变。
- 没有原提示词的上传卡片：填入成品图及简短可编辑说明，提示补充文字要求；如果保存过分析建议，可单独选择带入，不能冒充原提示词。
- 个别原参考图已丢失：保留可用内容，列出缺失项供补充，不悄悄忽略。
- 追加后超过当前模型参考图上限时，显示已选图片与角色，由用户取舍；确认前不改变草稿，不静默截断。
- 仍使用当前项目的模型、比例和数量，不因套用字体案例悄悄更换服务商或凭据。原生成参数保存在卡片内，可通过“沿用原参数”单独应用；模型不可用时明确提示。
- 没有当前项目时先选择目标项目，字体库保持全局，不默认回到来源项目。
- 填入后在输入区显示轻量提示“已引用：案例名称”，可以查看来源或撤销；用户编辑提示词不会修改已存卡片。

### 详情中的次操作

| 操作 | 带入内容 | 用途 |
| --- | --- | --- |
| 一键参考（主操作） | 成品图 + 原提示词 + 原参考图 | 整组复用，自行改字和调整 |
| 仅引用这张图 | 字体成品图 | 使用当前自己的提示词继续创作 |
| 复用原始生成条件 | 原提示词 + 原参考图，可选择原参数 | 在当时的创作条件上继续调整 |

第一版不增加独立“换字生成”模式；未来需要时再增加可选快捷入口，不改变用户已确认的默认操作。

原始提示词永久保留。识别文字和分析出的风格模板作为独立建议。用户修改后提交的提示词、引用顺序和参数在提交时形成快照，随后编辑卡片或切换项目不改变在途任务。

## 4. 与现有案例中心的关系

建议把字体卡片作为一条可复用案例资产，并增加“字体”类型。字体库提供专门的浏览和整组引用界面，案例中心通过“字体案例”筛选查看同一记录。

“存入案例库”保存/关联同一资产 ID，不维护两个互不一致的副本；修改名称、提示词和参考图在两个入口一致。现有通用/PPT 案例暂时保留原有行为，不为字体功能重做整个平台。

现有案例中心按项目存于 localStorage，GenerationCase 尚未完整保存原参考图、原模型等信息，当前“套用案例”也不会准确恢复参考组合。实现时必须补齐类型、持久化与复用链路。历史案例迁移采用可重复的增量复制、核对后保留原记录，不能直接覆盖。

## 5. 资产保存与性能

- 已确定全局共用，按用户隔离；来源项目作为追溯字段，跨项目均可引用。
- 原图和参考图保存为库管理的稳定本地资产/文件引用；远程临时 URL 需落地。以内容校验避免重复存储。
- 删除来源项目、清理回收站或归档项目时检查字体库引用，不能把卡片依赖的图片一起清掉。删除卡片不删除仍被其他资产/项目引用的文件；删除卡片提供撤销。
- 保存 recipe 时核验图片文件可读；存在缺项时保留可用内容，标记缺失，不宣称已完整备份。
- 库索引与图片分开保存，避免继续堆浏览器 localStorage 或把所有卡片写入现有大 JSON 的每一次保存流程。具体独立索引方案在实现前按桌面运行时兼容性确定。
- 网格分页或虚拟列表，缩略图按显示尺寸加载；视野外不解码原图。详情才取完整配方，大图预览才取原图。
- 批量上传/导入/分析采用有上限的后台处理，显示成功数和失败项，可重试；搜索、引用、下载不等待生图。
- 不随卡片持久化或导出 API Key。记录模型与服务商名称，使用时读取当前凭据。
- 支持卡片/分组导出包：原图、参考图、recipe 元数据一并打包，导入时校验文件和版本，并有重复处理规则。该能力可在核心流程完成后交付。

## 6. 第一版交付范围与顺序

### A. 可用的完整主流程（优先）

1. 左侧入口、全局卡片列表、一级分组、搜索、收藏、详情编辑。
2. 单图/批量上传，历史作品导入，画布和对话快捷收藏。
3. 成品图、原提示词、原参考图、参数与来源的完整保存及缺失标记。
4. 一键把整组资料填入对话、保留草稿与撤销套用、选择应用原参数；接现有并发队列和画布结果。
5. 案例中心字体入口映射同一资产，删除来源项目不损坏已收藏案例。

### B. 主流程稳定后增强

可选文字识别与风格分析、快捷换字、一组相同风格的多图合并卡片、衍生结果对比、导出导入包。第一版不加入多层目录、评分体系或复杂工作流。

## 7. 验收条件

- 上传一张只有图片的素材即可建卡，缺少原提示词不阻塞使用。
- 收藏已生成作品后，重启应用仍保留图片、原提示词和参考图顺序。
- 一键参考后，原提示词、成品图和原参考图均进入当前对话；文本可编辑，引用角色和顺序正确，不会自动发起生成。
- 原有草稿可保留，替换可撤销；提示词中的图号在追加后仍引用正确图片。
- 用户修改成其他文字后可正常提交；模型生成的字形、错字和风格相似度另做样本质量验收。
- 完整配方复用能核对原 prompt、引用顺序和记录参数；缺失项有明确提示。
- 删除来源项目/清空源记录后，已保存字体卡片及参考图依然可以打开与使用。
- 跨项目复用、草稿保留、模型不可用、超参考上限、失败重试和取消都可验证。
- 两组任务运行时，库搜索、点击引用、下载保持可用；大批量卡片列表只加载预览，性能以 1000 卡片基准实测记录，不宣称绝对零延迟。
- 案例中心与字体库访问同一资产，修改后不出现双份不同步数据。

## 8. 已确认的产品决定

1. 全局共用：所有项目都可以浏览和引用字体卡片。
2. 一键参考：字体成品图、原提示词和原参考图一起填入当前对话，用户自行修改后生成。
3. 保持轻量：一级分组、卡片和详情抽屉；默认沿用当前对话生图流程。
4. 详细方案与实现进度见 `字体库产品设计与开发文档.md` 和 `output/font-library-qa/report.md`。
