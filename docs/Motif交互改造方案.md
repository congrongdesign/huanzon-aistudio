# 环中 AIStudio：Motif 交互改造方案

版本：v1.0 · 2026-11-13 · 状态：方案，尚未实施

本轮只调研参考站、检查现有实现，并制作独立交互预览。没有修改业务代码、安装依赖、调用真实生图或更新本地安装版。

## 1. 推荐方向

把输入、选模型、调参数、等待结果连成一个清楚的创作流程：**输入时不被打断，提交后马上有反馈，等待时可以继续工作，结果一可显示就出现。**

参考 Motif 的组件组织和反馈方式，保留环中已有的画布、项目、提示词分组、模型服务配置和字体独立工作区。整体维持现有明暗主题，减少同时出现的控件，动效只解释状态变化。

优秀团队会先解决三个问题，再决定圆角和动画：

1. **谁拥有状态？** 草稿属于项目或字体会话；生成任务属于提交时的不可变快照；图片是否显示属于当前视图。三者独立。
2. **用户现在能做什么？** 正在生成不应阻止输入、复制旧内容、下载已有图片，也不应让后来选择的模型或风格改变已经提交的任务。
3. **哪些信息有依据？** 本地排队、请求发出、结果保存、预览解码可以检测；上游绘制进度只有服务端明确提供时才展示。

这次改造的重点是输入框、模型参数、任务反馈、结果呈现和对话滚动。范围内不增加大型任务中心或新的导航层级。

## 2. 调研结果：借鉴什么，如何适配

参考站是可以复制源码的组件库，其演示模型、价格、耗时和生成过程均不能直接作为真实服务能力依据。已实际体验输入框增高、模型菜单搜索、键盘选择、比例与清晰度切换、生图演示状态，并阅读相应文档与组件源码。

| 模块 | Motif 的做法 | 在环中采用的方案 |
| --- | --- | --- |
| 对话输入 | 单一圆角容器，附件在上，文字居中，操作在下；随文字增高并封顶 | 统一创作输入框，底部操作位置稳定，内容多时只滚动文字区 |
| 模型选择 | 搜索、推荐区、模型分组，长列表带厂商索引，键盘导航 | 常用/最近使用优先，展示实际服务来源；短列表省去索引，长列表再启用分组导航 |
| 比例与清晰度 | 比例图形、分段按钮、明确选中态 | 仅显示当前模型实际支持的选项；保留精确像素、格式等高级参数 |
| 对话等待 | 九点轻动效、状态文字与独立计时 | 安静的一行状态；计时只更新自身，不触发整块画布刷新 |
| 生图等待 | 固定形状的柔和流动底图，图片解码后揭示 | 仅在可见、进行中的卡片使用弱动效，先显示可靠状态，再显示就绪预览 |
| 图片出现 | 官方实现含约 1.4–1.6 秒透明度/模糊过渡 | 改为约 200–320ms 短淡入；缓存图片直接显示，减少动态时立即呈现 |
| 对话滚动 | 接近底部才跟随，向上浏览后允许停留 | 保留旧消息阅读位置和文字选择，提供“回到最新” |
| 发送/停止 | 文本流式回复期间，发送按钮改成停止 | 文本回复可以单独停止；生图按任务取消，仍可发送下一组任务 |

输入框实测：连续 14 行后文字区高度封顶 200px，内部滚动。模型目录在 760px 宽视口弹层没有撑宽页面。这些是参考组件观察，不代表本平台已经达到同样表现。

## 3. 现有实现中应一起解决的问题

| 当前依据 | 用户影响 | 本次处理 |
| --- | --- | --- |
| `src/app/page.tsx` 的 `GeneratingPlaceholder/getPhase(seconds)` 按秒数切换“排队/绘制/处理”等文案 | 看似有进度，实际不一定对应上游状态 | 接入现有任务队列状态；没有阶段依据时统一显示“正在处理 · 已等待…” |
| `chatMessages` 变化时无条件 `scrollIntoView({behavior:"smooth"})` | 用户复制旧对话、向上翻阅时可能被拉回底部 | 增加跟随/自由浏览两种状态，只在允许时跟随 |
| 输入框用 `contentEditable` 和 DOM 参考图芯片；输入时同步多份主页面状态 | 改造编辑器容易损失光标、引用身份和撤销；可能扩大重渲染 | 输入框局部持有编辑状态，以稳定引用 ID 导出草稿和提交快照 |
| 当前输入框粘贴先阻止默认行为，只读取纯文本；Enter 分支未见输入法组合判断 | 焦点在输入框时粘贴图片路径不完整；中文确认候选词存在误发送风险 | 图片/文字按 MIME 分流，增加组合输入保护；原生输入法测试列为必过项 |
| `@` 候选图列表使用原始图片地址，候选数量未分段 | 图多时选择参考图可能带来额外图片和 DOM 开销 | 128px 预览、限量首屏、搜索/按需加载 |
| 已有 `generation-queue.ts`、`generation-client.ts`、画布视口裁剪和预览图组件 | 基础能力已具备，重复建立队列会带来兼容风险 | 在现有能力上增加展示订阅和阶段字段，保持原有幂等与恢复规则 |
| 字体创作已有独立草稿、风格替换和任务快照 | 强行合并输入状态会使字体内容再次进入普通项目 | 复用外观组件，通过适配器分别绑定两套业务状态 |

上述为源码审计发现，不把未做过的原生输入法或性能实测写成已复现结论。

## 4. 用户会看到的具体变化

### 4.1 输入框：一个稳定的操作中心

结构从上到下：

```text
参考图缩略卡：图1、图2、上传中/失败、移除
字体区域专属：当前风格卡（如有）
输入文字：默认两行，随内容增高，到上限后内部滚动
模式 / 当前模型 / 比例 / 清晰度       更多参数 / 张数 / 发送
```

- 常规宽度 360–480px，依据输入框容器宽度布局；大屏上的窄聊天栏同样适用。
- 文字区建议高度上限 `min(180px, 25dvh)`，低高度窗口进一步收紧；展开更多参数不会挤压文字区。
- 常用参数在底栏就近展开；质量、格式、精确像素等进入同一个更多参数面板。主工具栏保留模型服务管理入口，避免两处出现互不一致的选择器。
- 上传、拖入、剪贴板图片使用同一附件状态：上传中、可用、失败。未上传完成不能作为可用引用发送，清楚指出待处理附件。
- 参考图卡片保留稳定身份、顺序、标签和来源；删除其中一张不重排其他引用身份。超过模型限制在提交前明确提示，不静默截断。
- Enter 发送，Shift+Enter 换行；中文/日文输入法候选词确认不触发发送；模型菜单、`@` 菜单打开时 Enter 先选择菜单项。
- 点击发送立即创建本地提交反馈；服务端接收成功后清空本次内容。若期间用户已输入新内容，依据草稿版本清理，绝不清掉新文字。接收失败恢复原提交内容，和新草稿冲突时提供恢复入口。
- 发送中的短暂防重复与后台生成分开；同一次提交复用 `requestId`。已接收后允许继续提交新的任务，达到本地队列容量时明确说明。
- 生成期间保留输入、粘贴、复制旧消息和图片下载。文本回复若只支持单路流式，用独立“停止回复”状态，不能把它变成全局生图锁。

字体区域额外显示当前风格卡；风格内容不反复拼接进个人文字。切换风格只替换风格包及其参考图，保留个人要求和个人参考图；沿用现有撤销风格机制。

### 4.2 模型：容易选，也知道请求发到哪里

默认底栏只显示当前模型；点击向上打开可搜索列表。

每行包含：模型名称、服务来源、已证实的能力，以及当前选中标记。服务来源必须是用户实际配置的服务名。厂商与中转服务是不同概念，同名模型绑定不同服务时保留两条独立记录。

- 顶部是收藏/常用与最近使用，其后按服务分组；搜索同时匹配模型名、别名和服务名。
- 沿用现有 `providerId + modelId` 绑定标识与路由解析，不用显示名称作为键。
- 模型切换先进行兼容性检查：不支持的比例/清晰度调整为有效值并说明；参考图数量过多时允许用户处理，不自动删除附件。
- 记住各模型上次有效参数；旧任务保留原来的模型、服务和参数快照。
- 不展示未经验证的“最快/最强”、虚构费用或估计生成时间。若供应商提供有效价格，可展示来源和计价单位。
- 文本模型采用紧凑菜单；只有后端支持并实际透传时才显示思考强度等选项。不能仅因模型名称看起来支持就露出无效控制项。
- 打开与搜索使用本地缓存，加载模型目录不阻塞菜单；网络刷新失败可继续选择已有配置，标注列表更新失败。

### 4.3 参数：看得懂，改变后立即确认

比例用小矩形表达 1:1、3:4、4:3、9:16 等形状；清晰度用紧凑分段按钮。选中状态通过底色、勾选和 `aria-pressed` 共同表达。

只呈现当前模型真实支持的组合。分辨率、质量与精确像素不是同一个概念，不把 VIP 像素设置粗略替换成统一 4K 按钮。更多参数里显示最终实际请求尺寸及必要的兼容说明。

### 4.4 生成：固定卡片、可信状态、各自取消

提交后立即在目标画布位置出现固定尺寸占位卡，包含本次提示词摘要、模型、状态与单任务取消。任务完成替换同一张卡，不重新排列画布。

同一批生成多张图，显示“已完成 2/4”；这是已完成数量，不当作单张图的模型计算进度。输入框附近仅保留“2 组任务进行中”的轻量入口，可以查看当前组和取消操作。

状态分成两条独立链路：

```text
任务：提交中 → 已接收/本地排队 → 处理中 → 结果已保存
                  ↘ 失败 / 取消请求 / 已取消或本地停止跟踪

显示：等待结果 → 获取预览 → 解码 → 可显示
                            ↘ 图片显示失败 → 重新加载
```

- “本地排队”来自本地队列；“上游排队/绘制/保存”仅在真实事件或响应能证明时显示。
- 上游无细分进度时显示“正在处理 · 已等待 38 秒”，不按秒数编造阶段或百分比。
- 图片已经返回但尚未可显示时写“图片已生成，正在加载预览”。生成成功与当前浏览器下载/解码成功分开。
- 轮询暂时断线显示“连接恢复中，任务仍在后台”；使用原任务 ID 恢复查询，不重新提交计费生成。
- 取消待执行任务可直接确认；运行任务如果供应商没有取消接口，应清楚说明“已停止本地等待，上游可能继续执行”，不能声称已终止上游或退费。
- 失败卡片保留提示词、参数和参考图快照；错误详情可展开，默认只给出简短原因及可执行动作。

### 4.5 结果：尽快出现，旧内容始终可用

先取适合当前显示尺寸的预览图，复用已有 128/256/512/1024/1600px 预览与画布视口逻辑。当前真实预览 URL 完成加载和解码后直接进入短淡入；原图下载独立进行，不等待原图解码才能操作。

必须处理：内存缓存已就绪、预览 URL 改变、组件离开视口、`decode()` 拒绝、预览失败回退原图。不能把原图 URL 的解码结果错误地绑定到另一个预览 URL，也不能因解码失败永久盖着加载层。

历史/缓存图片不重播生成动画；仅新完成且当前可见的结果淡入。显示失败的动作是“重新加载”，再次生成是另一项明确操作，避免为图片显示错误重复付费。

旧对话的复制/填入输入框、旧图片的下载都不受其他生图任务限制。用户正在上翻时，新消息只增加“回到最新”提示，不抢滚动位置、光标或文字选区。

## 5. 动效与性能预算

| 反馈 | 推荐时间 | 限制 |
| --- | --- | --- |
| 按下、悬停、焦点变化 | 100–140ms | 优先颜色/边框，不让文字随按钮明显缩放 |
| 菜单展开/关闭 | 140–200ms | 小幅位移与透明度，键盘操作不等待动画 |
| 参数选中态移动 | 180–240ms | 不改变整个栏位尺寸 |
| 新图片淡入 | 200–320ms | 解码后下一帧开始显示；缓存与减少动态模式立即显示 |
| 等待状态 | 轻微慢速流动 | 只在可见运行卡片上，视口外/窗口隐藏暂停 |

采用中性灰与现有品牌点缀色，文字保持对比度。参考站的大面积彩色流动与长模糊揭示不原样套到多图画布；优先预先定义的低成本渐变层与 transform/opacity，避免每张原图持续 blur、混合模式和全画布滤镜。

先将同时复杂动效的预算设为最多 4 个可见任务，更多任务用静态占位与状态文字；该数字为待实测初始值。计时默认每秒更新叶子节点，状态变化才更新对应卡片，禁止计时或逐字输出带动整个画布刷新。

“无延迟”的可实现部分是操作立即响应、缓存命中直接显示、可见图优先和持续可操作。外部模型推理、首次图片传输不能消除，不能用动画承诺真实零等待。

## 6. 工程拆分与迁移

建议结构，最终命名可按现有项目约定调整：

```text
components/creation/
  CreationComposer       输入、键盘、草稿与附件的通用外观
  ReferenceChip          引用/上传状态及删除动作
  ModelPicker            搜索、收藏、分组与来源展示
  GenerationSettings     能力约束下的比例/清晰度/高级参数
  GenerationTile         任务状态与媒体显示组合
  TaskStatusLine         状态文字、叶子计时、取消入口
  ConversationViewport   跟随底部/自由浏览/回到最新

lib/creation/
  model-capabilities     配置服务绑定与真实能力解析适配
  task-presentation      订阅现有任务队列，派生展示状态
  media-readiness        当前预览源的加载/解码与重试
```

组件复用不等于数据混用。普通画布适配现有项目草稿与消息；字体适配 `FontCreationWorkspace` 的会话、风格包和个人引用。任务读取提交快照，不反查后来变化的当前输入状态。

先复用现有 Radix/shadcn、cmdk 和 CSS 动效，不直接运行整个 Motif 注册表安装覆盖。Motif 的富文本版本包含 Tiptap 等依赖；它的外部纯字符串 value 也不足以恢复本平台已有参考图身份和结构。

先定义可版本化的结构草稿（文本段、引用 ID、来源与附件状态）及旧草稿转换，再评估编辑器方案。若保留现有编辑器能满足输入法、引用、撤销和粘贴测试，先做局部封装；只有不满足验收时再单独评估引入 Tiptap，不为视觉效果增加无必要的编辑器重量。

任务队列沿用现有四路并发、幂等 requestId 和批量轮询。可以扩充 `phase`、`phaseSource`、`phaseStartedAt` 等可选字段；旧接口没有该字段时回退为可信的粗粒度状态。展示更新按 taskId 订阅。跨窗口/服务重启保持原恢复规则，不静默重跑历史计费任务。

## 7. 实施顺序与交付界限

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| 本轮：方案 | 实际调研、源码核对、独立可点击预览、本文档 | 用户可审阅交互方向；不改正在使用的软件 |
| 第一步：基础与输入 | 采集现状性能基线；定义草稿/模型能力契约；封装输入框、模型和参数组件 | 引用身份、中文输入法、粘贴、服务路由与旧草稿恢复通过 |
| 第二步：任务与图片 | 接现有队列状态、单任务取消、预览解码与短淡入、对话滚动 | 两组并行仍能复制/下载/继续提交；断线不重复计费 |
| 第三步：字体与回归 | 字体工作区通过适配器使用通用交互；明暗主题、窄栏与动效降级 | 风格切换、个人内容、独立历史及任务快照语义不变 |
| 第四步：本地交付 | 在实施任务授权范围内备份、构建验证、更新安装版并实测 | 必要检查通过，保留可回退版本，验证用户数据可继续读取 |

本轮停在方案交付。后续开发按上述顺序推进，每一步形成可验证结果，避免一次性重写大型主页面。发布前基于已保存源码运行 `pnpm ts-check`、`pnpm lint`、`pnpm run build` 及针对性的现有测试；运行中应用的数据、草稿和未完成任务另做保护。

## 8. 验收标准

以下性能数字是**拟定目标，尚未测量**。实施开始记录同机、同窗口、同模型目录和图片集基线，并注明冷热缓存与真实任务/模拟任务。

| 场景 | 目标或必须满足的行为 |
| --- | --- |
| 输入与本地反馈 | 输入回显 p95 ≤50ms；提交后本地占位反馈 ≤100ms，不等待远端接收 |
| 模型菜单 | 已有目录的首次可交互目标 ≤100ms；搜索与键盘定位无明显阻塞；选中路由正确 |
| 图片就绪 | 解码就绪后下一帧开始可见；淡入在 320ms 内结束；缓存不附加等待 |
| 大图集与并行 | 500 张、1000 张历史图分别测试；两组任务、合计 4 个运行任务时，输入/复制/下载继续可用，关键交互 INP 目标 <200ms |
| 渲染范围 | 输入、计时、单任务更新不触发无关画布图片重绘；视口外无持续装饰动画，重点记录长任务与丢帧 |
