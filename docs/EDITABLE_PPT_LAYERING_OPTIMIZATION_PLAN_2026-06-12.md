# 分层功能优化方案

日期：2026-06-12

## 1. 目标

把现有“分层”能力从“规则识别 + PPT 导出”升级为“结构化识别 + 干净背景重建 + 可编辑图层导出”的稳定流水线。

最终要解决四件事：

1. 导出结果不再只是整页图片。
2. 文字尽量恢复为可编辑文本框。
3. 关键视觉元素尽量拆成独立图层。
4. 跨平台可用，Windows/Mac 都能跑。

---

## 2. 现状问题

结合当前代码，主要问题是：

1. OCR 能力不统一。
   - `runVisionOcr()` 只在 macOS 可用。
   - Windows 路径基本没有文字恢复能力。

2. 视觉拆层偏规则。
   - `detectVisualRegions()` 是网格颜色差分，不是语义级分割。
   - 容易把复杂区域当成一个大块，或者把多个对象粘在一起。

3. 背景重建不足。
   - `drawPreview()` 只是标注框预览，不是干净背景。
   - 导出时仍可能像“原图上叠文本”。

4. 导出策略不够细。
   - 文字、图片、形状、复杂区域没有形成更明确的分层策略。
   - 低置信度区域缺少统一兜底。

5. 前端复核能力还弱。
   - 目前更像识别结果面板，不像真正的图层检查器。

---

## 3. 优化原则

1. 可编辑优先。
2. 可保真兜底。
3. 不强行全对象化。
4. 识别和导出可重跑。
5. 结构化中间层统一所有输入来源。

---

## 4. 推荐路线

### Phase 1: 稳定基础分层

目标：让图片/PDF/PPTX 先能稳定得到“干净背景 + 可编辑文本层”。

任务：

1. 把 OCR 做成统一引擎适配层。
   - 主引擎：PaddleOCR。
   - 备选：macOS Vision。
   - 兜底：原始文本或空文本。

2. 文字 mask 先落地。
   - 根据 OCR bbox 生成文字遮罩。
   - 遮罩外扩，减少文字残留。

3. 背景修复接入本地/模型后端。
   - 优先本地 LaMa。
   - 可选 image2.0 编辑模型。

4. 导出背景优先使用 `cleaned_background`。
   - 不再只是原图加文本。

5. 页面级 debug 产物。
   - 原图
   - OCR JSON
   - 文本 mask
   - 干净背景
   - AST
   - 导出预览

验收：

1. PPT 导出后，文字可以单独编辑。
2. 背景里大部分文字已被去除。
3. Windows 也能识别文字。

---

### Phase 2: 元素层增强

目标：把人物、图标、产品图、插画等关键元素拆成独立层，而不是只拆文本。

任务：

1. 把当前视觉区域检测升级成“候选框 + mask refine”。
2. 引入 SAM/SAM2 做对象 mask。
3. 图层分类明确化：
   - `text`
   - `shape`
   - `image`
   - `icon`
   - `table`
   - `chart_or_complex`
   - `background`

4. 对复杂元素保留为局部图片层。
5. 对纯色卡片、按钮、底板尽量导出为原生 shape。

验收：

1. 页面里的主要视觉元素可以在图层面板中单独看到。
2. 不会产出大量碎片图层。
3. 导出 PPT 的编辑成本明显低于纯图片方案。

---

### Phase 3: 结构理解增强

目标：让复杂版式的页更像原稿，而不只是“拆开了”。

任务：

1. 接入 PP-StructureV3 或 MinerU 风格的结构 JSON。
2. 恢复布局关系：
   - 标题区
   - 正文区
   - 卡片区
   - 多栏区
   - 页脚区

3. 恢复文本层级：
   - 标题
   - 副标题
   - 正文
   - 说明
   - 页脚

4. 恢复更多样式：
   - 字号
   - 字重
   - 字色
   - 行高
   - 对齐

验收：

1. 商业汇报页、信息图页的结构更稳定。
2. 低置信度区域会被明确标记，而不是悄悄导出错层。

---

### Phase 4: 前端工作流升级

目标：让用户能看懂、能改、能重跑。

任务：

1. 当前页面变成真正的图层检查器。
2. 支持按元素类型筛选。
3. 支持单页重跑 OCR / 重跑背景修复 / 重跑对象分割。
4. 支持导出模式切换：
   - `editable_first`
   - `fidelity_first`
   - `hybrid`

5. 低置信度提示明确显示。
6. 失败页支持独立重试，不影响整批任务。

验收：

1. 用户能很快判断哪一页需要复核。
2. 用户能直接定位到某个图层并修正。

---

## 5. 技术拆分

建议拆成 5 个可插拔模块：

1. `ocr-engine`
2. `layout-engine`
3. `mask-engine`
4. `background-cleaner`
5. `pptx-exporter`

对应到当前代码：

1. `src/lib/editable-ppt/import.ts`
   - 改成流程编排，不再塞满所有逻辑。
2. `src/lib/editable-ppt/export.ts`
   - 只做 AST -> PPTX。
3. `src/components/EditablePptWorkbench.tsx`
   - 只负责交互、复核、导出和重跑。

---

## 6. 推荐实现顺序

### 第一步

先做跨平台 OCR 统一化。

### 第二步

接入文字 mask 和干净背景生成。

### 第三步

把视觉元素分层升级为 SAM/refine 路线。

### 第四步

补结构 JSON 和布局恢复。

### 第五步

完善前端图层检查器和重跑机制。

---

## 7. 风险控制

1. 不追求一次性全对象化。
2. 不让大模型直接输出 PPT 结果。
3. 不把重模型直接塞进 Next.js route。
4. 不用单一引擎做所有页面类型。

---

## 8. 成功标准

1. 导出 PPT 不是整页图片。
2. 文字可编辑。
3. 关键视觉元素可单独移动或替换。
4. Windows 和 macOS 都可运行。
5. 每页都有置信度和复核状态。

---

## 9. 结论

最优路径不是继续把规则调得更复杂，而是把能力拆成三层：

1. OCR 和结构识别。
2. mask 与背景修复。
3. PPTX 导出与前端复核。

这样可以先解决“可用”，再逐步接近“像原稿”。
