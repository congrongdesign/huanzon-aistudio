# 字体创作独立工作区与风格切换方案

状态：已开发并完成隔离环境验收，已更新本机安装版。本文保留产品规则，并在第13节记录实际实现。本方案取代第一版中“回到当前普通项目并追加资料”的默认行为。

## 1. 现状与问题定位

升级前，`handleUseFont` 获取 `currentProjectIdRef`，`queueFontDraft` 写入普通项目的 `hz_chat_draft_...` 并导航到 canvas。字体创作因此与原项目共享草稿、聊天上下文、作品与部分设置。

升级前，`buildFontComposer` 默认把已有文本和引用放在前面，再拼接新案例。拼接之后只有一份普通文本/引用数组，没有记录哪段文字和哪张图属于上一个字体风格。因此重复选择风格会累积，不适合“试用A、再改试B”的使用方式。

这两个问题需要统一修正：把字体创作视为独立的工作环境，把选中的风格视为一个可替换的创作条件。

## 2. 产品决定

1. 字体库继续全局共用，最左侧“字体”入口保留。
2. “字体”内部提供“作品库 / 字体创作”两个同级视图，不增加多级目录。
3. 卡片主操作改为“用此风格”。点击后进入字体创作，首次建立字体专属创作会话；之后恢复最近会话。
4. 切换风格继续在同一字体创作会话内进行，不为每次点击新建项目或会话。
5. 字体创作的草稿、对话、作品、选中风格与设置独立保存。原有普通项目保持原来的草稿与状态。
6. 默认一次只使用一个字体风格，选B即用B替换A。第一版不提供混合多风格模式。
7. 主操作只准备创作资料，由用户点击生成，不自动发起付费请求。

## 3. 页面设计

桌面视图：左侧为可收起的风格选择区，中间为字体生成结果，右侧为字体专属对话与输入区。沿用当前应用的颜色、字体、控件和主题。

顶部清楚显示“字体创作 · 当前设计”，提供“返回作品库”和“新建设计”。顶部切换使用户能区分整理素材与进行创作。字体会话列表放在一个简洁的最近设计菜单中，避免增加一整棵项目树。

结果区保留已有作品的查看、参考、下载、收录功能。生成结果属于该字体会话；可通过显式“添加到普通项目”操作带回其他画布，不自动写入以前打开的项目。

窄窗口将风格区折为侧滑选择器，保留结果与输入切换。工具栏和生成按钮始终可达；卡片预览完整显示字形。

## 4. 输入区：分清风格资料与个人要求

输入区显示两块逻辑内容，但不要求用户学习技术概念：

### 当前风格

显示成品图、卡片名称、参考图数量与“更换 / 移除”。原提示词和原参考图放在可展开的“风格资料”中，用户可以查看和修改这次创作使用的副本。原卡片内容保持不变。

该区域就是从字体卡片带入的内容。换风格时，整个区域被新风格替换，包括上一次风格的成品图、提示词、原参考图、来源关系以及该区域内的临时修改。

### 你的要求

继续使用自由输入框，例如：“把文字改成‘秋水长天’，黑字白底，笔画更细”。用户自己上传的参考图也属于这部分。切换风格时保留这些内容，不增加必填换字表单。

生成时组合“当前风格资料 + 你的要求 + 你自行添加的图片”。强调用户对目标文字与输出的明确要求优先；不同模型的字形质量仍需实际检查。

## 5. 风格切换规则

| 场景 | 规则 |
| --- | --- |
| 首次选择A | 在字体创作中显示A的成品图、提示词和原参考图 |
| 输入自己的文字后选择B | 完整替换A，保留自己的文字、额外参考图和当前字体创作设置 |
| 再次选择B | 保持现有状态，不重复插入，不清除对B已做的修改 |
| 移除风格 | 移除风格区域与其专属引用，保留个人要求和个人参考图 |
| 撤销换风格 | 恢复上一个风格及其修改副本；不回滚用户此后在个人输入区新增的文字 |
| 同一图片同时由用户添加、也属于风格 | 移除旧风格角色，保留用户角色；底层输入可以合并文件，界面保留角色说明 |
| B读取失败 | 保持A及草稿，显示失败重试 |
| B含缺失图片 | 明确显示缺失项与修复入口；不把其他图片改指为该缺失图片 |
| 超过模型参考上限 | 先预览候选组合并选择，确认后一次替换；取消保持A不变 |
| 快速选择A→B→C | 只有最后一次选择C可以提交，晚到的A/B响应不能覆盖C |
| A已提交生成，再选择B | 已提交任务继续使用A的快照；新输入使用B，任务不会串风格 |

普通风格切换不弹出重复确认。风格修改副本自动保存，撤销可恢复上一个；个人内容始终保留。

## 6. 上下文隔离

独立工作区必须同时隔离 UI、状态、持久化、后台任务和模型上下文。只换页面标题或偷偷创建一个普通项目不能满足要求。

字体生成默认按当前风格和当前要求准备请求，旧作品保留作浏览历史，不自动将之前试过的A风格对话重新塞进B的请求。后续若提供多轮字体对话，必须明确绑定字体会话和风格修订，显式引用作品才影响生成。

字体创作单独保存模型、比例、数量。首次创建时可以从当前可用配置初始化；后续在字体区调整不会改写普通画布的创作设置。服务商配置与凭据继续使用现有统一管理，不复制密钥到会话或配方。

## 7. 状态与数据设计

建议使用结构化状态，而不是从拼接后的文本中猜测边界：

```ts
type FontCreationSession = {
  id: string;
  ownerId: string;
  title: string;
  activeStyle: {
    cardId: string;
    cardVersion: number;
    selectionRevision: number;
    recipeSnapshot: FontStyleSnapshot;
    promptOverride?: string;
  } | null;
  userDraft: StructuredComposerDocument;
  userReferences: OwnedReference[];
  settings: FontGenerationSettings;
  revision: number;
  createdAt: string;
  updatedAt: string;
};

type OwnedReference = {
  referenceId: string;
  assetKey: string;
  owners: Array<
    | { kind: 'user' }
    | { kind: 'style'; cardId: string; selectionRevision: number }
  >;
};
```

风格命令：`selectStyle / removeStyle / undoStyle / editStylePrompt`。个人输入命令独立，撤销风格不整体覆盖 composer 草稿。

`FontStyleSnapshot` 保存本次使用的成品图、提示词、按序原参考图、卡片来源；用户随后编辑源卡片不会改变已提交任务。

引用在文档中用稳定 referenceId 关联，最终提交时再映射为当前模型所需图号。只解析来自 recipe 的原图号；不对整段用户输入做正则删除、重编号或匹配“字体案例”标题。没有来源标记的旧文本无法可靠区分自动内容与用户内容，不能猜测删除。

## 8. 存储与现有系统衔接

新增 `font-creation-store` 和 `/api/font-creation/sessions`，负责专属会话、草稿版本和生成结果索引，与普通项目分离。复用现有全局字体卡片文件与字体库索引，不维护第二份卡片副本。

改造生图请求的目标上下文为带类型的结构：

```ts
type GenerationDestination =
  | { kind: 'canvas'; projectId: string }
  | { kind: 'font'; sessionId: string };
```

服务端验证目标归属。字体任务只落入对应字体会话结果；普通历史/项目列表不展示字体任务。显式“添加到项目”通过独立操作建立目标记录，保留来源信息。

复用现有模型适配、后台并发队列、缩略图、下载、错误处理与字体收录能力；将“在哪里保存结果”的逻辑抽到目标适配层。不能把 projectId 设为 null 后依赖所有未分组图片充当字体结果，这会再次引入混淆。

字体会话与引用资料使用专属存储目录；写入有原子性、版本冲突保护和按用户隔离。图片文件可复用字体库的内容寻址存储。删除会话不删除全局卡片；删除全局卡片不损坏已保存会话/任务所用的资产快照。

## 9. 异步切换与并发可靠性

先准备候选风格、核验可用图片、计算引用数量，再一次性提交状态。每次选择递增 selectionRevision，取消旧读取并在提交时再次比较修订；仅 AbortController 不足以防止已到达的旧响应覆盖。

会话和工作区切换后，旧响应也不得写入新会话。任务提交绑定 sessionId、styleRevision 和不可变 recipe。生图进度更新按 taskId 路由到正确会话，不能使用当前打开的页面作为保存目的地。

已有下载、风格选择和草稿输入不等待其他生图任务完成。保留当前限流、缩略图懒加载和有界卡片分页。

## 10. 旧版本兼容

不搬移原有普通项目的聊天或作品，不自动清除以前被插入到项目的文字。旧数据没有可靠的逐段来源，猜测清理会伤到用户内容。

升级后，“用此风格”默认进入独立字体创作，从全局卡片重新准备资料。原普通项目保留。用户需要旧内容时可显式复制到字体区；不会在首次进入时自动导入旧项目全部上下文。

旧版“整体替换输入”的逻辑不再作为默认入口。字体库、案例中心字体卡片、字体创作内切换风格三个入口统一调用同一条 selectStyle 流程。

## 11. 开发顺序

1. 字体会话类型与存储、生成目标适配层；先确保历史和结果隔离。
2. 独立字体创作页面与草稿恢复，接通现有队列和作品收录。
3. 结构化风格区域、个人输入与引用归属；实现替换、移除、撤销。
4. 统一所有字体入口，处理超限、缺失、快速点击与任务快照。
5. 执行回归、视觉验收、备份与本机安装；保留此前版本以便回退。

## 12. 验收标准

- 从任意普通项目点字体卡片，不改变该项目草稿、历史和作品。
- 字体会话重启后能恢复当前风格、个人输入、引用、设置和结果。
- 选择A，输入个人要求，再选择B：当前风格资料中A的文字和专属图片均消失；个人内容保留。
- A与用户共用一张图片时，切到B不误删用户图片。
- 切换、移除、撤销均不触发付费生成；重复选择不叠加。
- 快速点击与慢响应时最后选择生效；失败或取消超限选择保留原状态。
- A任务运行时切B、切会话，A结果仍归A提交时的会话并保留A配方。
- B请求不夹带A的旧会话风格；引用身份与图号可核对。
- 普通项目列表/历史/恢复与字体会话均无数据混入。
- 字体生成、下载、收录闭环通过隔离模拟接口检验，再检查浅深主题和窄窗口。

本方案的关键不是增加更多按钮，而是让“字体创作属于哪里”和“哪些内容由当前风格控制”在界面和数据中都有清楚的边界。


## 13. 开发实现说明

### 13.1 模块与数据

- `src/components/FontCreationWorkspace.tsx`：独立字体创作页面，桌面三栏，窄窗风格选择器与作品/对话切换。
- `src/lib/font-creation-types.ts`：会话、草稿、风格快照、任务与目标类型；`compileFontCreation` 编译本次输入。
- `src/lib/font-creation-store.ts`：会话原子存储、版本检查、风格命令、任务快照、显式复制到普通项目。
- `src/lib/run-font-generation.ts`：复用现有模型适配执行字体任务，结果写入字体资产存储，不创建普通 `image_records`。
- `src/app/page.tsx`：字体入口的“作品库 / 字体创作”同级导航；卡片使用入口仅传递风格请求。
- `src/lib/font-library-store.ts`：复用不可变文件存储；新增字体任务收录，保存当次完整配方。

实际会话格式为 `FontCreationSession` schemaVersion 1：`activeStyle` 保存 cardId、cardVersion、UUID revision、成品图、原参考图、原提示词与使用模式；`draft` 单独保存 userText、userReferences、stylePrompt、excludedReferenceIds、settings。`styleUndo` 最多8项，只保存风格相关状态。`runs` 保存当次编译提示词、个人要求、完整风格快照、参数、文件引用、状态与结果。

每个个人参考图有稳定 referenceId；风格引用ID包含风格修订和原图序号。同一文件保留各自角色，编译时按文件 key 去重。个人文字不会经过风格图号替换。

会话目录：`local-data/font-creation/<ownerHash>/<sessionId>.json`。图片继续复用 `local-data/font-library/files`，文件按用户隔离、按内容寻址。JSON临时写入后原子更名；同会话修改有文件锁及revision检查。生成进度不提升草稿revision，避免轮询导致输入冲突。

### 13.2 接口

| 接口 | 方法/动作 | 行为 |
| --- | --- | --- |
| `/api/font-creation/sessions` | GET | 列出当前用户字体会话；带 `id` 读取完整会话及协调任务状态 |
| 同上 | POST | 创建会话；multipart上传个人图片；`action: export`显式复制作品到目标项目 |
| 同上 | PATCH | 保存带revision的草稿与名称；`action: style`选择风格，`styleAction: remove/undo`移除或撤销 |
| `/api/font-creation/generate` | POST | 按sessionId、revision、requestId创建不可变任务并加入现有队列 |
| `/api/font-library` | POST `action: collect-font` | 收录已完成字体任务的作品、原提示词、参数与参考图 |

接口沿用本机登录身份。直接从普通生成接口提交font destination会被拒绝，避免绕过字体任务快照。API Key只用于当前队列执行，不保存到会话或任务配方。重启后中断任务标记失败，不自动重新付费生成。

### 13.3 交互与恢复

草稿450ms防抖保存，每次输入即时写入浏览器恢复文档；离开后未发出的保存可以在相同revision恢复。所有保存、换风格、提交命令串行；风格读取另有递增序号，处理晚返回请求。重新选择同一卡片同模式保持修改副本。

保存冲突停止继续覆盖，保留本机草稿，可复制个人文字或下载完整JSON恢复副本。重新载入前再留一份本机归档，随后读取服务端版本。任务提交期间新增的输入不被响应覆盖。

参考图超限先显示选择面板，确认前不修改原风格，取消保留原状。缺失原图显示缺失状态，生成不会把其他图片冒充为缺失项；补图入口保留在作品库详情。移除风格不会删除个人引用。

列表使用现成128/512缩略图、懒加载、卡片24条分页；创作结果首批40项、按需加载更早作品，对话记录显示最近8条。展开生成设置后输入区内部滚动，生成按钮保留在可达位置。

### 13.4 验证与交付边界

自动检查：字体会话/快照/替换专项、字体库回归、队列回归、TypeScript、针对改动模块的ESLint、生产webpack构建。浏览器使用独立LOCAL_DATA_DIR、5099端口与本地模拟模型接口，覆盖风格A/B切换、重复选择、移除/撤销、个人输入保留、超限选择、晚返回请求、会话恢复、在途任务、取消/失败、下载/收录/导出及保存冲突。

视觉检查覆盖浅深主题、1440×960、760×700与安装版原生1600×972窗口。真实安装应用不导入测试卡片，不发起付费生成；真实模型的文字准确度、风格还原质量仍由所选模型决定。

升级前备份程序与最新数据；保留普通项目及旧版已插入内容，不做推断迁移。安装后核对主数据库及原字体资产哈希。安装与验证明细见 `output/font-workspace-qa/report.md`。
