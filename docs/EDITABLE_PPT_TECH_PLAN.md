# 图片转分层可编辑 PPT 技术方案与分阶段开发计划

## 1. 背景与目标

目标是在环中AIStudio 内新增一个独立能力模块，把 `PPT 截图 / PDF / 图片集 / 图片版 PPT` 转成尽量接近原稿结构的 `可编辑 PPTX`。

核心要求：

1. 保留原稿文字内容。
2. 尽量恢复版式、图片位置、色块和基础图形。
3. 输出结果不是整页截图塞进 PPT，而是文本、图片、形状尽量分层。
4. 对复杂区域采用“可编辑优先，必要时图片兜底”的混合策略。

不建议一开始追求 100% 全对象化。正确路线是：

`输入文件 -> 页面渲染 -> 元素识别 -> 结构重建 -> PPT 对象生成`

---

## 2. 技术方案

### 2.1 总体思路

这类能力本质上不是单一大模型一步生成 PPT，而是一个分阶段处理链路：

1. 输入标准化
2. 页面渲染与预处理
3. 页面元素拆解
4. OCR 与文本结构恢复
5. 形状/图片/图标重建
6. 布局关系恢复
7. PPTX 输出
8. 失败页重试与人工修正

建议采用：

- `Next.js / Node.js` 负责：上传、任务管理、存储、导出、前端预览
- `Python 服务` 负责：OCR、版式理解、图形检测、结构解析

这是最稳的工程形态。

### 2.2 输入层设计

支持三种输入：

1. `PPTX`
2. `PDF`
3. `图片包（PNG / JPG / WebP / ZIP）`

处理策略：

1. `PPTX` 先经 `LibreOffice` 转 PDF，再拆页成图片
2. `PDF` 用 `Poppler / pdftoppm` 渲染为高清页面图
3. `图片包` 直接作为页面输入

统一输出为：

- `page images`
- `page metadata`
- `task records`

### 2.3 页面预处理

每页建议执行：

1. 尺寸标准化
2. 颜色增强
3. 降噪
4. OCR 友好版本生成
5. 边缘与版心区域估算

建议工具：

- `sharp`
- `Poppler`
- `LibreOffice`
- 可选 `OpenCV`

### 2.4 元素拆解

每页要识别出以下对象类型：

1. `text`
2. `image`
3. `shape`
4. `icon`
5. `table`
6. `chart_or_complex`
7. `background`

每个对象建议输出：

```json
{
  "id": "el_001",
  "type": "text",
  "bbox": [120, 90, 980, 120],
  "zIndex": 10,
  "rotation": 0,
  "opacity": 1,
  "groupId": "group_01",
  "confidence": 0.94
}
```

### 2.5 文本恢复

这是 V1 到 V3 都最关键的部分。

需要恢复：

1. 文本内容
2. 行分组
3. 段落分组
4. 标题/正文/脚注层级
5. 对齐方式
6. 字号估算
7. 字重估算
8. 字色提取
9. 字体近似映射
10. 行高与段落间距

建议技术：

1. `PaddleOCR` 负责中文优先 OCR
2. `PP-Structure` 负责文档结构增强
3. 复杂页可引入 `VLM` 做二次校正

### 2.6 图形恢复

优先恢复常见 PPT 形状：

1. 矩形
2. 圆角矩形
3. 圆形
4. 直线
5. 分割线
6. 标签底框
7. 常见卡片底板

需要恢复的样式：

1. 填充色
2. 描边色
3. 描边宽度
4. 透明度
5. 圆角
6. 阴影
7. 旋转

### 2.7 图片恢复

对图片区域：

1. 从原页裁切独立图片
2. 保留原比例
3. 去掉明显白边或背景误裁
4. 作为独立图片对象写入 PPT

对复杂插画、照片、复杂渐变、难以矢量化内容：

1. 不强行重建
2. 直接保留为图片层

### 2.8 布局关系恢复

这一步决定“是否像原稿”。

重点恢复：

1. 对齐关系
2. 间距规律
3. 卡片分组
4. 标题区/正文区/页脚区
5. 左右栏/多栏结构
6. 同类模块重复规律

建议设计统一的中间结构 `Slide AST`。

### 2.9 中间结构建议

建议每页先输出统一 JSON，再由 JSON 生成 PPTX。

```json
{
  "pageIndex": 1,
  "width": 1920,
  "height": 1080,
  "background": {
    "type": "color",
    "fill": "#F6F3EE"
  },
  "elements": [
    {
      "id": "title_1",
      "type": "text",
      "bbox": [120, 90, 980, 120],
      "zIndex": 10,
      "text": "年度业务复盘",
      "style": {
        "fontSize": 34,
        "fontWeight": 700,
        "fontFamily": "Microsoft YaHei",
        "color": "#1A1A1A",
        "align": "left",
        "lineHeight": 1.2
      }
    },
    {
      "id": "card_bg_1",
      "type": "shape",
      "shape": "roundRect",
      "bbox": [110, 240, 780, 420],
      "zIndex": 2,
      "style": {
        "fill": "#FFFFFF",
        "stroke": "#E5E5E5",
        "radius": 18
      }
    },
    {
      "id": "image_1",
      "type": "image",
      "bbox": [980, 220, 620, 520],
      "zIndex": 6,
      "src": "slice://page1/image_1.png"
    }
  ]
}
```

### 2.10 PPT 输出策略

项目当前已经使用 `PptxGenJS`，建议直接复用。

对象映射：

1. `text` -> `addText`
2. `shape` -> `addShape`
3. `image` -> `addImage`
4. `table` -> 原生表格或图片兜底
5. `chart_or_complex` -> 图片兜底

输出原则：

1. 能转文字就转文字
2. 能转简单形状就转形状
3. 太复杂就保留为图片

### 2.11 后端建议模块

建议新增独立模块，而不是塞进现有 PPT 工作台主流程。

模块名称建议：

- `可编辑PPT`

建议 API：

1. `/api/editable-ppt/import`
2. `/api/editable-ppt/jobs`
3. `/api/editable-ppt/jobs/[id]`
4. `/api/editable-ppt/jobs/[id]/pages/[page]`
5. `/api/editable-ppt/jobs/[id]/pages/[page]/reparse`
6. `/api/editable-ppt/jobs/[id]/export`

任务状态建议：

1. `queued`
2. `preprocessing`
3. `ocr`
4. `layout`
5. `reconstructing`
6. `ready`
7. `failed`

### 2.12 前端建议模块

建议页面能力：

1. 导入面板
2. 页面缩略图区
3. 元素识别预览
4. 图层面板
5. 修正面板
6. 导出面板

### 2.13 关键风险点

#### 1. 字体误差

问题：

- 原稿字体本机没有
- 替换字体后换行会错

解决：

1. 建字体近似映射表
2. 以“宽度接近优先”而非“名字一致优先”

#### 2. OCR 对了但版式错

问题：

- 文字识别正确，但文本框尺寸不准

解决：

1. 保存行级 bbox
2. 做文本框回归修正
3. 前端允许人工微调

#### 3. 图表与复杂表格

问题：

- 很难完全语义化恢复

解决：

1. V1 直接图片兜底
2. V2 先做简单表格
3. V3 再考虑复杂图表结构化

#### 4. 页数多时速度慢

解决：

1. 多页并发
2. 队列化处理
3. 分阶段导出
4. 先返回预览结果，再生成最终 PPTX

## 3. 分阶段开发计划

### 3.1 V1：先做可用版

目标：先做到“文字可编辑 + 图片分层 + 基础导出”。

#### 功能范围

1. 上传 `PDF / 图片包 / PPTX`
2. 自动拆页
3. OCR 提取文字
4. 页面图片作为背景或切片图片
5. 文字恢复成可编辑文本框
6. 导出 `PPTX`
7. 前端支持逐页预览

#### 技术栈

1. `LibreOffice`
2. `Poppler`
3. `sharp`
4. `PaddleOCR`
5. `PptxGenJS`

#### 前端范围

1. 新建“可编辑PPT”模块入口
2. 上传区
3. 页面列表
4. 结果预览
5. 导出按钮

#### V1 验收标准

1. 文字在 PPT 中可编辑
2. 图片位置基本正确
3. 20 页以内项目稳定可用
4. 不追求复杂图形的完整恢复

### 3.2 V2：做成真正分层版

目标：加入基础图形和布局恢复。

#### 新增能力

1. 识别矩形、圆角、线条、标签底框
2. 恢复背景色块
3. 恢复多栏结构
4. 恢复卡片结构
5. 恢复简单表格
6. 恢复图层顺序
7. 支持人工修正后再导出

#### 前端新增

1. 图层树
2. 元素属性面板
3. 文本块合并/拆分
4. 手动标记元素类型

#### V2 验收标准

1. 常见商务页、封面页、目录页、信息卡页稳定恢复
2. PPT 中能明显看到多层对象结构
3. 不再只是“整页图片 + 文字覆盖”

### 3.3 V3：对标专业级体验

目标：逼近成熟产品效果。

#### 新增能力

1. 图标独立提取
2. 复杂布局理解
3. 自动卡片分组
4. 表格智能恢复
5. 图表局部结构化恢复
6. 多语言排版适配
7. 批量任务队列
8. 页级失败重试
9. 低置信度页面提示人工复核
10. 智能质量评分

#### 可扩展高级能力

1. 页面类型自动分类
2. 自动生成母版建议
3. 自动抽取页面设计规范
4. 导入后直接进入 AI 美化工作台继续处理

#### V3 验收标准

1. 多数商务 PPT 页面可达到高可用恢复
2. 批量处理稳定
3. 支持生产环境长任务运行与失败恢复

## 4. 与当前平台的结合方式

不建议直接修改现有 `PPT 工作台` 逻辑。建议新增一个并列模块：

1. `可编辑PPT`
2. `PPT 工作台`
3. `批量模块`

职责划分：

1. `可编辑PPT` 负责导入、识别、分层恢复、可编辑导出
2. `PPT 工作台` 负责统一风格美化、黑白灰素稿、上色、审核导出
3. 后续支持从 `可编辑PPT` 一键把恢复结果推送到 `PPT 工作台`

这样不会破坏你现在已有工作流。

---

## 5. 推荐的开发顺序

最稳的顺序：

1. 先做 `V1`
2. 先验证 20 页以内的稳定性
3. 再做 `V2`
4. 等 `V2` 稳定后，再和工作台打通
5. 最后做 `V3` 的复杂页面与批量能力

原因：

1. 风险最低
2. 每一阶段都能单独交付
3. 不会因为一开始追求过高还原度而迟迟无法落地

---

## 6. 当前结论

这个能力完全值得做，但要严格按工程化分阶段推进。

最核心的原则只有两个：

1. 先做“可用”，再做“高保真”
2. 先做“混合重建”，不要一开始执着于全对象化

最终路线建议：

1. `V1` 先解决“文字可编辑”
2. `V2` 再解决“形状和分层”
3. `V3` 再解决“复杂布局和生产级批量”
