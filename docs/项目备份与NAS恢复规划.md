# 项目备份与 NAS 恢复规划

日期：2026-11-15。状态：调研与方案，尚未实施。未运行真实项目备份、恢复、清理或 NAS 迁移；尚未确认用户 NAS 的实际挂载路径。

## 产品方向

统一为「资产 → 项目备份」。用户看到项目缩略图卡片，通过「备份到 NAS」「恢复到画布」完成主要操作。一个项目只有一张卡片，各次备份放进版本历史。

默认备份保留当前项目；收起项目、释放本机空间是单独的可选操作。这里的“备份”指单向保存可恢复的历史版本，不承诺多台电脑同时编辑、双向实时合并。

## 现状核查

- `src/app/page.tsx` 同时存在「同步备份」「NAS 归档」、项目行备份按钮以及设置里的归档入口。同步面板又包含「一键同步并清理」「仅同步并保留本机」。
- `/api/project-package` 使用 v1 `.hzproj.zip`，主要覆盖项目、图片、对话、参考图、提示词和技能。打包循环遇到读不到的资源会跳过，因此“生成了 ZIP”不能代表完整备份成功。
- `/api/cloud-sync` 使用上述 v1 打包器，保存独立的同步配置与索引；每次保存一个新的项目包。
- `/api/project-archive` 使用 v2 `.hzarchive.zip`，覆盖更多对象，包括画板、标签、设计资产及关联记录、灵感素材。已有资源 SHA-256 校验、落盘后校验和后台任务，可作为新功能的基础。
- v2 归档默认 `deleteAfterBackup !== false`，现有一键同步明确传入 `true`，会在校验后清理原项目。新方案必须改变默认行为及前端完成回调，不能仅改按钮文案。
- 现有恢复在原项目不存在时恢复原 ID，有冲突时创建副本。尚需建立稳定的备份来源关联，避免恢复、再备份之后出现重复卡片。
- 当前归档条目无缩略图字段。案例与风格包存在按项目划分的浏览器 localStorage 中，不能假定服务端打包器已经包含。其他新功能的项目关联数据也需逐项核对。
- 已有目录选择、储存管理、图片读取回退等能力可复用，但备份目的地必须独立于图片库位置、NAS 素材来源配置。

## 页面与交互

资产区域增加独立的「项目备份」视图，作用域是当前账号的全部项目，不随当前画布项目筛掉备份。

页面结构：

1. 顶部：备份位置「NAS / AIstudio备份」、连接状态、选择文件夹/更改位置、备份项目。
2. 工具栏：搜索项目；全部、待备份、待更新、已备份、仅 NAS。连接异常单独提示，不混为项目数据状态。
3. 中间：项目卡片网格，支持多选后批量备份；每个项目一张卡片。
4. 卡片详情：较大预览、备份内容清单、历史版本、校验情况、恢复与任务记录。
5. 底部或全局任务入口：当前阶段、文件进度、成功/失败项目数及重试。

卡片示意，内容仅为样例：

```text
┌──────────────────────────────┐
│         画布缩略图             │
│                              │
├──────────────────────────────┤
│ 春季品牌视觉                  │
│ 24 张图片 · 3 个画板           │
│ 最近备份：11 月 15 日 09:30    │
│ 已备份 · 本机可用              │
│ [打开画布]               […]  │
└──────────────────────────────┘
```

本机不存在的项目显示「仅 NAS」，主按钮改为「恢复到画布」；本机内容有变化则显示「待更新」，操作为「更新备份」。卡片不以 ZIP 文件名、设备名和完整路径作为主要信息。

封面优先生成整个画布的缩略预览；对于极大画布，选择主要画板或代表性图片拼图，支持后续手动更换。封面和目录元数据保存在 NAS，也缓存在本机，NAS 离线仍能浏览已知卡片。封面不参与项目内容恢复，也不替代可编辑数据。

## 三条主要流程

### 首次备份

进入资产 → 项目备份 → 用文件夹选择器选择 NAS 的「AIstudio备份」目录 → 检查连接及写入权限 → 多选当前项目 → 备份。

后台保存一致的项目快照和真实资源文件，读取落盘内容校验后显示「已备份」。当前项目继续可用。没有变化再次备份应跳过，并显示“没有需要更新的内容”。

### 收起项目

在已备份项目的更多菜单选择「收起项目并释放本机空间」。先展示将收起的项目、最近成功版本及可释放空间，用户明确执行后才清理。

清理前复查：最近备份是否完整、项目是否又发生变化、NAS 是否仍连接。变化则先完成新版本，或阻止清理。执行期间短暂阻止该项目写入；共享资源仍有引用则保留。对于云端数据库和对象存储，另行明确范围，不能将“本机空间”当作删除云端数据的授权。

收起后从工作中的项目列表移出，但资产里的缩略图卡片和版本记录保留。

### 恢复使用

点击仅 NAS 项目的「恢复到画布」→ 校验指定版本 → 恢复资源与关联数据 → 成功后提供「打开画布」。恢复保留 NAS 原备份。

本机已有对应项目时，优先提供打开已有项目；需要历史版本时恢复为副本，避免静默覆盖。副本保留来源信息，后续独立编辑与备份有清晰归属。重复点击和重试复用任务身份，防止同一次恢复生成多个项目。

## 数据与可靠性

### 稳定目录与版本

持久化区分项目身份、备份版本身份、当前本机项目 ID 以及来源关联，不能靠项目名或时间戳文件名合并。跨设备使用同一 NAS 仓库时，挂载路径可以不同，仓库身份保持一致。

第一阶段继续使用完整项目包，统一调用 v2 备份引擎；每个版本独立可恢复。内容无变化不再建版本。第一阶段不能宣称具备增量传输或跨版本去重，历史完整包的占用应如实展示。

后续有真实容量或耗时需求，再增加按内容哈希存储的资源对象和增量快照。删除旧版本必须计算资源引用，不能删除其他项目或版本仍依赖的资源。第一阶段不自动删除历史版本。

### 完整性与一致性

- 建立项目关联数据清单：画布图片及几何/层级关系、画板、对话、参考图、标签、设计资产及版本/图层、灵感素材、项目提示词与技能等；逐项核对现有 Schema。
- 项目案例、风格包等浏览器数据，先设计持久化与导出桥接；当前浏览器拿不到的数据必须明确标注，不能声称已完整备份。全局字体库、账号配置、共享提示词库需明确归属；API 密钥不放入项目备份。
- 数据库快照与不可变资源引用绑定；用项目内容修订标识或内容摘要判断变化，不能只看可能未随图片移动/对话变化更新的项目时间字段。
- 缺少必需原文件时标记备份不完整，列出原因并保留原项目。只有封面失败可以使用占位封面，不影响有效备份。
- 先写临时文件，再校验，再发布已完成版本与目录信息；不把半成品显示为可恢复版本。SMB/NAS 的重命名与落盘行为需要在真实设备验证。
- 清理是独立阶段。备份成功、清理失败应分别显示；批量任务逐项目记录结果，不用一句“失败，原项目未清理”覆盖已经完成的其他项目。
- 恢复使用暂存项目和事务/补偿机制，成功后再出现在正常项目列表；失败可重试，不留下可误打开的半成品。

### NAS 断连与多端

- 已挂载 NAS 是第一阶段支持范围；界面写清楚操作的是运行 AIStudio 服务的电脑，网页不能直接写访问者电脑上的任意目录。
- 通过已登记仓库标识核对目标目录；NAS 断开时停止写入，禁止在挂载点同名的本机空目录继续“备份成功”。
- 离线时保留本机缓存卡片，提示 NAS 未连接，恢复和清理操作暂不可用；不因扫描失败清空目录。
- 同项目任务互斥；跨进程和跨设备写入使用经过 NAS 验证的仓库协调方式，采用独立版本文件和可重建索引，避免共同覆盖同一个 JSON。
- 任务持久化、逐阶段检查点和幂等提交；中断后识别已提交版本，再决定重试或继续，不能假定底层文件传输天然支持续传。

## 旧备份兼容

连接目录后识别旧同步索引、旧归档索引、v1 `.hzproj.zip`、v2 `.hzarchive.zip`；扫描已知位置并提供主动重新扫描/导入旧文件入口，避免只扫描新格式。

原文件先保留，通过读取包内项目身份建立卡片、版本和封面。无法可靠识别同一项目时单独展示，不按同名自动合并。v1 包展示其实际内容范围和可用性，不能升级标签后就声称包含原包未备份的数据。

首次导入记录识别成功、需检查、无法读取的数量；损坏包明确可见。新目录可从包内清单及旁车元数据重建索引，不依赖某台电脑上的数据库才能找到备份。

旧入口收敛：移除画布工具栏的独立同步/归档按钮和项目行上的重复 NAS 备份图标；设置里仅保留跳往资产项目备份的入口。便携项目包的导入/导出如仍需保留，收进更多菜单，并统一备份数据格式。

## 实施顺序与验收

第一阶段：统一入口、目录选择、旧包识别、缩略图卡片、批量手动备份、版本详情、一键恢复、后台任务及失败重试。先验证完整的“备份—恢复—继续编辑”闭环。

第二阶段：在修订检测、共享资源引用保护及失败补偿通过验证后，开放「收起项目并释放本机空间」。

第三阶段：按需增加用户主动开启的自动备份、可配置版本保留与增量去重。多端实时协作单独设计。

必须验证：

1. 同项目多次备份一张卡片；有变化保留多个版本，无变化跳过；改名不变成新项目。
2. 旧格式包实际可识别、预览和恢复；缺少的内容明确说明。
3. 恢复后图片、画布坐标、画板、对话及关联资产一致；可继续编辑、保存、重开并再次备份。
4. 本机有更新时禁止用过期版本直接清理；恢复冲突默认不覆盖；共享资源不误删。
5. 缺原图、NAS 断连、磁盘满、任务中断、索引损坏、并发点击时，状态与已提交结果一致，可重试。
6. NAS 离线仍有缓存卡片；换电脑连接相同仓库能够重建项目列表并恢复。
7. 真实安装版、真实 NAS 挂载环境执行完整恢复演练；源码检查和 ZIP 校验不能替代恢复演练。
