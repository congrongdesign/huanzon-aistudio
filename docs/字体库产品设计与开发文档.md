# 字体库 · 产品设计与开发文档

版本：1.0；状态：第一版已开发、验收并更新本机安装版本。适用：本机安装的环中 AIStudio。

## 1. 产品定位与成功标准

将值得复用的字体设计图片收为有来源、有配方的案例。用户的主路径是「收录作品 → 整理分组 → 一键参考 → 修改对话 → 生成 → 再收录」。全局共用，所有项目可引用。字体库管理设计图片，不提供 TTF/OTF 字体安装。

第一版必须完成上传、历史收录、完整配方保存、一级分组、搜索收藏、详情编辑、整组引用与草稿撤销、案例中心入口和本地持久化。不得只交付页面原型。文字识别/AI 风格分析、打包导入导出、同风格多图合并和对比留作后续版本，不在第一版放置不可用按钮。

## 2. 设计判断

成熟设计团队会先减少用户决策，再处理视觉。这里把“浏览作品”和“编辑配方”分开：卡片以作品为主，复杂资料进入详情抽屉；同一个按钮始终表示准备对话，不直接启动付费生成。

沿用应用的主题、字体、shadcn/Radix、lucide 图标与 Tailwind，不为单个功能更换整套视觉系统。设计差异程度 4/10、动效 2/10、信息密度 5/10。中性底色、克制边框、作品完整展示；不用仪表盘指标、渐变装饰和多层目录。8px 间距基准，卡片 12px 圆角，控件高度至少 36px。浅色/深色均可用，焦点清晰，尊重系统减少动态效果偏好。

### 信息结构

- 最左侧“字体”入口，与画布、提示词同层。
- 页面顶部：标题“字体库”、全局说明、搜索、上传、从历史收录。
- 左侧约 192px：全部、收藏、最近使用、未分组、用户一级分组；窄窗折为横向筛选。
- 主区域：完整预览的图片卡片，名称、示例文字、收藏、一键参考。24 张一页，固定分页保持 DOM 有界。
- 详情抽屉：大图、预览底色切换、名称/示例文字/分组/复用提示词、原始配方、参考图、来源与缺失状态。
- 案例中心增加“字体案例”入口，读取同一套全局数据；编辑不产生两个副本。

### 状态与操作

空库提示上传或历史收录；搜索为空可清除筛选；加载显示骨架；失败提供重试。上传逐张反馈，成功项保留，失败项可重新选择。删除卡片为软删除，提供撤销；删除分组将作品归为未分组。分组改名、删除在组管理弹窗完成。

## 3. 数据契约

`FontCard`：id、ownerId、title、sampleText、groupId、favorite、cover、references、prompt（可编辑复用内容）、originalPrompt（只读原始内容）、parameters、source、warnings、createdAt、updatedAt、lastUsedAt、deletedAt、version。

`FontFile`：key、url、width、height、label、role、missing。封面与参考图独立存放，按内容 SHA256 去重；相同内容可承担多个引用角色，元数据不丢角色。

`GenerationRecipe`：schemaVersion=1、实际 prompt、原用户输入（可用时）、有序 referenceImages 与 labels、model、size/imageSize/quality/background/outputFormat/moderation、来源项目/图像/任务/消息 ID、sourceFontCardId、createdAt。不得保存密钥、请求鉴权、带凭据的服务地址。

原始配方只读，修改复用提示词不会改原始 prompt。上传无 prompt 时标为未知，不捏造。旧记录仅按明确图像 ID 取对应操作；不根据时间相近或文本类似匹配别的任务。缺失参数显示“未记录”，丢失参考保留位置与说明。

## 4. 存储与一致性

本地 Electron 运行时与 Node24 的内置 SQLite 不一致，不引入未验证的原生数据库。第一版使用独立 `local-data/font-library/`：按用户分隔的版本化索引、内容寻址文件、预生成 128/512 预览、generation-recipes 快照。与主 `db.json`、浏览器 localStorage 分离。

索引短事务采用独占锁目录和原子临时文件 rename。导入先完成图片落地再提交索引，重复收录在提交时再次检查 sourceImageId。失败不会生成半张卡片；文件可暂为孤立文件，第一版不自动物理回收，避免误删。软删除可恢复。索引内包含版本，更新提供 version 冲突检测，禁止用旧抽屉覆盖新编辑。

专用 `/api/font-file/[key]` 根据当前用户读取原图/预览。文件独立于来源项目，删除源图片、回收站或项目不会损坏字体库。复制文件失败必须显式记录，封面失败不创建卡片。远程素材有超时、大小限制；只接受可解码的 JPG/PNG/WebP，单张最大 25MB，像素最多 8000万。

当前交付面向本机模式，云端部署需要替换存储适配器，接口返回明确的模式错误，不能悄悄写入云服务器临时磁盘。

## 5. API

均使用现有身份机制，并按 owner 隔离；错误返回 `{error}`，不把内部文件路径返回前端。

| 接口 | 行为 |
|---|---|
| GET /api/font-library | q/group/filter/page 搜索分页摘要；同时返回分组与总数 |
| GET /api/font-library?id= | 完整卡片与 recipe |
| GET /api/font-library?history=1 | 当前用户历史图片按项目、关键词、日期筛选后分页 |
| POST /api/font-library (multipart) | 上传一张成品图，名称可从文件名预填 |
| POST /api/font-library (JSON) | action=collect，以 imageId 精确收录历史作品；重复返回原卡片 |
| PATCH /api/font-library | 编辑卡片、收藏、软删除、恢复、标记使用，支持版本冲突 |
| POST/PATCH/DELETE /api/font-library/groups | 一级分组增改删 |
| GET /api/font-file/[key]?w=128/512 | 按用户读取缩略图，原图用于放大/下载/生成 |

批量操作由客户端逐张提交，服务端图片处理最多两个并发；不使用全局生图 loading 锁。API 页面只传摘要，不把全库原图或完整配方送进 React。

## 6. 一键参考与草稿安全

1. 点击前取得当前项目草稿，按项目保存快照；若没有项目，用现有创建项目机制创建目标项目，绝不切到来源项目。
2. 默认追加，生成清晰的「字体案例：名称」文本段落；次操作可替换，且保留原草稿以撤销。
3. 引用顺序为“已有草稿图 → 字体成品图 → 原有序参考图”。相同文件合并图片输入但保留角色标签。原提示词中的图号映射到新序号；原始记录不变。旧自动生成的引用说明移除后由生成流程重建。
4. 全部参考超出当前模型上限时，先显示选择弹窗。用户确认前不改变草稿，不静默截断。取消无副作用。缺失引用显示提醒，并保留文字编号的缺失标记，避免错指其它图。
5. 默认保留当前模型、比例、数量和配置。详情提供显式“沿用原比例”选项；模型/质量保留在配方中供查看，避免自动切换凭据或服务商。
6. 回到当前画布待输入框挂载后填入，输入保留可编辑文本和引用 chip。已填入提示提供撤销；用户点击现有发送按钮才执行。
7. 实际提交时保存 prompt、引用顺序和参数快照；并发任务不读取后续被用户改动的卡片。

## 7. 收录入口

上传：选择多图或拖入，逐张建卡；只有图片和名称必需。详情可补示例文字、分组和复用提示词，原参考图可上传补充（保留原始来源缺失标记）。

历史：可按项目、关键词、日期查找，分页多选，顺序提交显示结果。画布右键及对话生成图片旁均提供“收藏到字体库”，用真实记录 ID 收录。对于只存在聊天链接而找不到唯一记录的旧消息，进入历史选择，不自动猜配方。

## 8. 性能边界

卡片使用 `loading=lazy`、`decoding=async` 和预先生成缩略图。页容量 24，不无限堆 DOM。搜索 200ms 防抖并取消旧请求，防止晚到请求覆盖新筛选。详情按需读取。图片处理池并发 2，上传与生图队列独立，常用按钮不依赖全局生成状态。

1000 卡片的本地索引、分页响应、缩略图与切页做实测记录。目标是点击即时反馈，不承诺原图、磁盘和网络的绝对零延迟。首次远程收录可等待，之后使用本地副本。

## 9. 验证与发布

自动验证：上传格式/大小、用户隔离、重复收录、并发写入、版本冲突、分组删除归未分组、软删除恢复、源项目删除后的文件读取、完整 recipe 的引用顺序、草稿追加映射与超限选择、重启后读取、1000卡片分页。

浏览器：真实交互检查空态、上传、搜索、分组、编辑、收藏、历史、详情、引用、撤销、案例中心同记录；浅/深主题和窄窗截图；监控控制台错误。生成接口用隔离数据与模拟响应验链，不发起付费生成。

运行类型检查、新模块 lint、webpack 生产构建。安装前备份已装 app 和最新用户元数据，保留当前配置，确认无近期在途任务后仅正常退出环中 AIStudio，替换 standalone、签名校验、重开验证。所有其它应用与 Photoshop 未保存文档不受影响。安装失败还原 app；不使用旧数据库覆盖用户最新数据。

## 10. 后续阶段

可选 OCR/风格分析应记录为建议，经用户启动且可修改，不写成原提示词。后续提供配方包导出导入、同风格多图卡片和衍生结果对比。根据实测增长再替换为兼容桌面 runtime 的 SQLite/服务端存储；保持接口契约不变。
