# 环中 AIStudio × affectUI 界面改造评估

日期：2026-11-19。范围：改造建议与组件适配评估，未修改业务代码、安装应用或用户作品，未发起付费生成。

## 检查依据

- 已核实当前进程来自 `/Applications/环中AIStudio.app`，安装应用从 `Contents/Resources/standalone/server.js` 加载运行服务，页面为 `http://127.0.0.1:5001/`。
- 直接连接正在使用的桌面窗口，检查了实际项目画布、输入框、对话记录，并进入提示词页读取内容。桌面窗口随后不再提供可连接页面，其余界面在独立浏览器中检查同一安装版运行服务；未重启桌面应用。
- 独立浏览器尺寸为 1440 × 1000，检查字体创作、字体库、案例中心、模型页、提示词详情、导入任务。该浏览器不共享 Electron 的 localStorage，因此个人模型缓存、输入尺寸等配置不能与桌面窗口完全等同。模型可用性未测试。
- 对照当前源码和 `docs/UI_STYLE_GUIDELINES_V2.md`。以当前中性 Motif 规范为准，不采用旧 `DESIGN.md` 的紫色玻璃风格。
- 已通过接入的 affectUI 工具检索组件并读取 Chat Composer、Prompt Library、Agent Inbox、Agent Queue、Filter Menu、Command Menu、Settings / Models、Agent Trail、Tool Call Card、Dropzone、Message Actions、AI Answer 文档；另外读取了 `filter-menu-clean` 和 `prompt-library-clean` 源码以确认适配边界。

## 建议顺序

| 顺序 | 改造位置 | 可借鉴资源 | 主要收益 | 估计改动范围 |
| --- | --- | --- | --- | --- |
| 1 | 提示词使用前填写变量 | Prompt Library clean | 把收藏的长提示词变成可直接复用的配方 | 中 |
| 2 | 画布与字体创作输入区 | Chat Composer clean | 参数更容易读懂，保持输入和参考图关系清晰 | 中 |
| 3 | 后台任务反馈 | Agent Inbox clean；批量吞吐场景再用 Agent Queue | 跨工作区查看状态，已完成任务不再显示处理中操作 | 中至大 |
| 4 | 提示词、字体、案例筛选 | Filter Menu clean | 组合筛选、条件可见、单项移除 | 中 |
| 5 | 对话与生成结果 | Message Actions clean；保留已有结果组件 | 结果更易比较、定位和再次使用 | 中 |
| 6 | 全局快捷入口 | Command Menu clean | 快速跳转和执行常用操作 | 中 |
| 7 | 模型配置概览 | Settings / Models 的分区方式 | 快速确认不同用途当前默认使用什么模型 | 小至中 |
| 8 | 上传和空状态细节 | Dropzone clean、Empty State | 上传失败和筛选无结果时有明确下一步 | 小至中 |

范围估计用于比较优先级，不是工期承诺；任务中心跨越多个独立业务状态，成本最高。

## 1. 提示词从“复制长文”升级为“填空使用”

安装版提示词库当前显示 286 条。抽查可见 `[INPUT_TEXT]`、`[CITY_NAME]`、`[country]` 等变量或示例占位符；详情直接展示正文，使用回调传递整段文字。当前快捷选择也以完整文本为单位。源码中画布接收使用提示词的回调采用替换输入语义。

建议保留现有图片卡片和管理页，在“使用”之前加一个轻量填写面板：选择配方 → 填写标题、城市或产品等变量 → 查看最终提示词 → 明确选择“追加到输入”或“替换输入”。普通无变量提示词维持快捷使用。模板原文保留，填写值作为使用时的参数，不改写收藏资产。

例如“城市字窗”可以显示城市名称输入框，并同步更新提示词中的重复变量。超过六个变量时使用带标签的表单，避免在长句中塞满输入框。

适配边界：affectUI 原组件使用 `{name}` 形式的变量，不能直接识别本库中的所有方括号、中英文和混合写法；需要规范化适配并允许人工确认。不要把所有括号内容都自动视为变量，示例末尾的固定赋值也需要处理，避免和用户填入值冲突。原组件粗略 token 数按约四字符估算，不应直接作为中文准确用量显示。

参考：[Prompt Library](https://www.affectui.com/components/prompt-library?style=clean)。

## 2. 输入区优化信息层级，保留自由调节尺寸

实际桌面窗口的画布输入区较宽，但底部模型名仍截断为 `gpt-image-2…`；参数集中在同一行。字体创作则同时展示风格卡、参考图、长输入及模型参数。软件已经支持拖动调整输入框尺寸，这项能力应保留。

建议借鉴 Chat Composer 的主次关系：正文和引用为主要区域，底部保留模式、模型、生成按钮；数量、比例、分辨率使用简短且可读的标签，低频参数集中于参数面板。长模型名通过布局和完整名称提示解决。字体风格继续独立标识，并清楚区分风格参考与个人参考图。

保留现有中文输入法保护、粘贴图片、@引用、发送期间继续输入、停止对应回复、草稿与尺寸记忆等行为。affectUI Chat Composer 的演示语音、连接应用、授权状态不属于当前需求，不随组件一起增加。

参考：[Chat Composer](https://www.affectui.com/components/chat-composer?style=clean)。

## 3. 任务中心首先解决“现在该做什么”

现有导入任务面板已经有收录数、完成数、需处理数、暂停、继续、重试和撤销，字体整理与项目备份也有自己的反馈。不应重复宣称这些能力尚不存在。

实际导入面板中，已完成的三个批次仍显示“暂停整理”“重试”“停止后续整理”“撤销本批新增”。这些控件与完成状态不匹配，是可以先做的小改造。

建议分两步：

1. 先按真实状态控制操作。运行中显示可用的暂停或停止；失败时显示原因和针对失败项的重试；完成时显示结果入口，其他操作进入更多菜单。已结束批次默认折叠。
2. 再增加全局任务入口，聚合生成、导入整理、项目备份等任务，分为进行中、需处理、已完成，点击能返回对应项目或资产。保留现有五个工作区，不必新增一个常驻工作区。

Agent Inbox 更适合这里的任务汇总；Agent Queue 用于确有排队、并发槽位和限流的批量任务。大量历史记录需分页或搜索，不能把几百条都塞进看板。

所有阶段、耗时、进度和操作必须来自业务事件。无法获取百分比时显示明确的等待状态；取消行为准确反映停止范围。affectUI 某些组件未提供回调时会在内部模拟状态，必须改为受控接入实际任务。

参考：[Agent Inbox](https://www.affectui.com/components/agent-inbox?style=clean)、[Agent Queue](https://www.affectui.com/components/agent-queue?style=clean)。

## 4. 让三库筛选可以组合且能看见条件

提示词页目前有分组、小类别、单标签和搜索；字体页有分组、收藏、最近使用和文本搜索；案例中心有比例、标签、排序和缩略图大小。这些基础能力应继续沿用。

建议借鉴 Filter Menu：在列表上方显示可移除的当前条件，支持标签多选和一键清除。提示词优先“用途 + 风格 + 比例”；字体优先利用已保存的风格与标签；案例继续保留比例、标签、排序和缩略图尺寸。不同字段之间按 AND，同一字段多选按 OR，并在交互文案或帮助中说明。搜索继续独立存在，排序不混进筛选。

保持作品完整 contain 展示，不为了卡片整齐裁切字体作品。字体库已有收藏、最近使用和分组，不需要再做一份新的收藏页。

参考：[Filter Menu](https://www.affectui.com/components/filter-menu?style=clean)。

## 5. 对话结果应便于比较与继续创作

实际画布对话中有多批四张结果。已有扇形预览、展开全部、回到最新、复制和替换输入，应在此基础上优化。源码的展开结果使用固定 3:4 容器与 cover 展示，对横版作品不利于比较完整构图。

建议保留扇形入口，展开时采用适配作品比例的预览；结果提供“定位画布”“继续编辑”“收录到库”等明确动作。对话消息动作可借鉴 Message Actions 的轻量按钮和复制完成反馈。生成完成后展示真实模型与参数摘要，模型身份必须取自已保存数据。

版本切换只有在保存了明确版本关系后才增加；不能把独立生成结果直接伪装成版本。AI Answer 适合有真实检索来源的回答，普通生图反馈无需附加来源卡。Tool Call Card 可用于高级日志，面向设计用户默认展示中文操作摘要，无需暴露 JSON。

参考：[Message Actions](https://www.affectui.com/components/message-actions?style=clean)。

## 6. 全局命令入口适合高频使用

当前有提示词快捷选择的 cmdk 菜单，未在主工作区发现全局命令面板。可以增加 ⌘K / Ctrl+K：跳转工作区、查找项目、打开提示词、查看任务、适应全部等。按当前上下文提供操作，保持正常导航可见。

初期只接已有搜索和操作；跨库全文搜索属于额外数据能力，不能只装一个菜单就视为完成。删除、清空或产生付费调用的命令应保持各自原有交互语义。

参考：[Command Menu](https://www.affectui.com/components/command-menu?style=clean)。

## 7. 模型配置适合补概览

现有模型页已经按服务组织模型，支持搜索、用途筛选、激活、默认、手动添加和批量管理。适合借鉴 Settings / Models 的默认模型分区：顶部直接列出对话、生图等用途的默认模型和来源服务，下方保留现有卡片与详情。

服务连接成功、模型已激活、实际调用成功是不同信息，界面应分别表达。独立检查浏览器未共享桌面模型缓存，因此本次不据此判断用户模型配置存在故障。

模型速度、质量、价格等属性仅在有可靠来源时展示。Settings / Models 是整页资源，其文档列出了 Hugeicons 和其他组件依赖，接入成本高于基础单文件组件；这里更适合借鉴结构。

参考：[Settings / Models](https://www.affectui.com/screens/settings-models)。

## 8. 上传与空状态作为后续细节

现有拖入提示、先保存原图再后台整理、重试与暂停恢复可继续复用。Dropzone 适合补充单文件上传反馈、失败原因、重试；长时间任务进入任务面板。过滤无结果与从未收录内容，应分别提供“清除筛选”和“开始收录”等下一步。

原组件未提供 onUpload 时会模拟上传，需要接入现有真实上传流程。上传进度与后台 AI 整理进度分开呈现。

参考：[Dropzone](https://www.affectui.com/components/dropzone?style=clean)、[Empty State](https://www.affectui.com/components/empty-state?style=clean)。

## 接入原则

- 优先 clean 样式，适配当前 Motif 语义 token，保留组件已有的键盘操作、焦点管理和克制动效。源码中存在白色与蓝色默认值，深色模式和主题切换需要实际适配。
- 不整体替换现有 shadcn/Radix 基础组件；在 PromptLibrary、任务摘要、筛选器等独立业务区域逐个验证。
- 接入必须传递真实业务数据与回调，移除样例内容、演示计时、模拟上传或内部演示状态迁移。
- 本次是评估，没有完成组件集成，也没有运行集成后的浅深主题、窄窗、中文输入法或付费流程测试。
- 后续如实施，按项目约定同步源码与正在使用的本机安装版，并在桌面窗口验收。此次没有安装更新。
