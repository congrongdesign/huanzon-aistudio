# 深色模式 UI 一次性优化策略（Adobe 黑白灰风格）

日期：2026-06-13  
适用范围：主画布、聊天面板、项目栏、图库、资产库、Prompt Manager、PPT Workshop、Batch Module、Node Workflow、全局弹窗/抽屉/Popover

---

## 1. 目标与原则

### 1.1 目标

1. 全平台深色模式统一为 **黑白灰中性风格**（去霓虹、去发光、去高饱和渐变）。
2. 强化“识别性”：信息层级、可交互元素、状态反馈在不依赖高饱和颜色的前提下依然清晰。
3. 强化“深浅度”：通过表面层级、线框密度、阴影强弱形成明确的空间关系。
4. 一次性修复核心模块视觉割裂，建立后续可持续维护的规则。

### 1.2 设计原则

1. **少色系**：深色模式主色限定中性灰阶，状态尽量用明度差 + 形状/文案辅助表达。
2. **层级优先**：先保证 L0/L1/L2/L3 表面层级，再处理局部装饰。
3. **可读优先**：标题 > 正文 > 说明文 > 辅助信息的对比梯度稳定。
4. **交互优先**：hover/focus/active/disabled 必须可见，不依赖发光效果。

---

## 2. 问题分解（按风险优先级）

### P0（必须立即修复）

1. 多模块仍存在蓝紫渐变、霓虹色文字、发光阴影。
2. 深色下边框线条有的过亮、有的几乎看不见，导致结构识别不稳定。
3. 主按钮、次按钮、禁用按钮风格混杂，操作优先级不明确。
4. 弹窗/抽屉背景与页面层次不分，遮罩和内容表面冲突。

### P1（本轮完成）

1. 批处理、PPT、Prompt、节点工作流等子系统风格割裂。
2. 小字号（10~11px）在深色模式对比不足。
3. 状态标签（成功/失败/警告）过于依赖色相区分。

### P2（持续优化）

1. 历史硬编码色值沉淀较多，后续需要继续语义化替换。
2. 图库/资产库局部细节（筛选栏、统计 chips、详情条）继续精修。

---

## 3. 统一视觉系统（Dark）

### 3.1 表面层级（Depth）

1. L0 页面底：`#1b1b1b`
2. L1 主容器：`#202020`
3. L2 卡片/面板：`#252525`
4. L3 浮层/弹窗：`#2b2b2b`
5. 线框：`rgba(255,255,255,0.10~0.18)`（按层级递增）

### 3.2 文字层级（Readability）

1. 主要文字：`#ececec`
2. 次级文字：`#c8c8c8`
3. 辅助文字：`#9e9e9e`
4. 禁用文字：`#737373`

### 3.3 阴影与边界（高级感）

1. 禁止彩色发光阴影。
2. 统一使用黑色柔阴影 + 极弱内高光：
   - 轻层：`0 6px 18px rgba(0,0,0,.24)`
   - 中层：`0 10px 26px rgba(0,0,0,.30)`
   - 强层（modal）：`0 18px 36px rgba(0,0,0,.42)`
3. 边框比阴影更重要：先用线条划分结构，再用阴影补充层次。

---

## 4. 识别性策略（不靠高饱和颜色）

### 4.1 按钮体系

1. 主按钮：浅灰实体底（高对比黑字）+ 细边框 + 明确 hover。
2. 次按钮：深灰底 + 细边框 + hover 提亮。
3. 幽灵按钮：透明底 + 边框，hover 加轻背景。
4. 禁用按钮：独立禁用底色/边框/文字，不仅是 opacity。

### 4.2 状态体系（Success/Warning/Error）

1. 深色模式下不使用鲜艳绿黄红做大面积底色。
2. 用“明度 + 边框样式 + 图标/文案”区分：
   - success：较亮弱底 + 实线边框
   - warning：中亮弱底 + 虚线边框
   - error：较深弱底 + 左侧强调线

### 4.3 交互状态

1. hover：背景提升 4~8% 明度。
2. active：内阴影或边框增强，不用发光。
3. focus-visible：2px 可见环，保证键盘导航可追踪。
4. selected：弱底 + 强边 + 文案强调（三要素至少两项）。

---

## 5. 组件分域策略

### 5.1 全局（app-shell / gallery / asset / agent）

1. 清除彩色 gradient、drop-shadow、霓虹 ring。
2. 统一输入框与选择器样式。
3. 统一弹窗遮罩（深遮罩）与弹窗表面（L3）。

### 5.2 PPT Workshop

1. 继承深色基线，不再出现紫蓝发光按钮。
2. 保留流程识别，但通过文案、边框和图标区分阶段。

### 5.3 Batch Module

1. 顶部品牌图标改为中性卡片样式。
2. 各类功能按钮统一到主/次/危险三级。
3. 进度条和状态 chip 去高饱和，保持高识别。

### 5.4 Prompt Manager

1. 左侧导航、列表项、弹层统一边框与层级。
2. 快捷选择器、版本面板、导入导出弹窗统一表面规则。

### 5.5 Node Workflow

1. 节点连线与节点卡片去紫蓝光效，改中性灰阶。
2. 保留节点类型识别：图标 + 标题 + 布局位置，而非颜色堆砌。

---

## 6. 执行计划（本轮）

### Phase A：设计基线收口（全局）

1. 在 `globals.css` 新增终态锁层，建立深色统一 token 映射。
2. 全局清理彩色渐变、发光阴影、过饱和高亮。
3. 统一按钮/输入/边框/弹窗规则。

### Phase B：模块接入（结构性）

1. 为 Batch/Prompt/Asset/Node 等模块补充稳定根类名。
2. 用根类名做 scoped 覆盖，避免全局误伤。
3. 修复显著硬编码冲突点（节点连线、信息提示块、头部图标等）。

### Phase C：验收与回归

1. 深色全链路走查：画布、聊天、图库、PPT、Batch、Prompt、节点、弹窗。
2. 对照清单验证层级、识别性、可读性。
3. 执行类型检查并确认预览可访问。

---

## 7. 验收标准（必须全部通过）

1. 深色模式下不再出现明显蓝紫霓虹发光效果。
2. 主/次/禁用按钮在任意模块均能一眼区分。
3. 线框在所有核心面板可见且不过亮。
4. 弹窗与页面有清晰分层（遮罩 + 表面 + 边框 + 阴影）。
5. 小字号（10~11px）在深色背景可读，不糊成一片。
6. 状态反馈不只靠颜色，至少有文案或形态差异。
7. 关键页面无“局部仍旧老风格”的明显割裂。

---

## 8. 参考依据（外部规范）

1. WCAG 对文本与非文本对比要求（4.5:1、3:1 等）用于定义可读性底线。  
2. Apple HIG / Material / Adobe Spectrum 的色彩与层级实践用于校准“低饱和 + 高层次”的方向。  
3. NNGroup 深色模式可用性研究用于避免“只追求好看不追求识别”的误区。
