# 生成中整理画布稳定性修复

## 现象与分析

生成占位、成品图片位置、视角、可视裁剪属于同一次交互，但原实现把整理与适应视角分在两个阶段，用50毫秒定时器连接。定时器持有旧图片数组；任务结束、再次整理或切换项目可能在期间发生。可视裁剪又经effect同步视角，因此新变换可以搭配旧裁剪范围，全部节点暂时被移除。隔离环境通过重置视角后立即整理捕捉到节点数为0的DOM状态，随后恢复，数据本身仍在。

另外，局部重绘、AI编辑、扩图、上传等异步回调使用提交时的占位坐标，整理后结果可能跳回旧位置。空间索引缺乏有限值检查，异常无穷坐标可能导致循环无法前进；本次未在真实数据库发现异常数值，这属于防御修复，不能宣称是用户现场唯一根因。

## 处理

- 整理纯计算结束并校验后提交；位置与适应视角在同一次事件内更新，删除50毫秒延迟及旧数组闭包。
- 可视裁剪遇到新的受控视角时直接使用该视角，拖拽时继续使用低频pan快照，不增加拖动渲染频率。
- 相机计算提取为纯函数，空内容、隐藏窗口、无效矩形不产生NaN/Infinity；异常矩形不进入空间索引。
- 占位节点保留任务身份，不删除、不重新生成。常规任务已有的当前位置继承逻辑保留；重绘、编辑、扩图、上传和恢复历史任务完成时也继承当前坐标，保存最终布局。
- 两次独立↑的间隔放宽到900毫秒；长按、输入法候选、修饰键、其他键打断规则保留。
- 普通画布和字体生成框删除计时以及每秒刷新计时器，保留状态和加载动效、删除键取消任务。

## 验收

逻辑回归覆盖空画布、只有任务、成品混合多任务、非法几何、任务完成继承位置、10000个矩形与大图连线场景。界面使用隔离目录与本地模拟模型，覆盖多组任务、重复整理、缩放平移、完成、刷新恢复、取消、项目切换、普通和字体输入恢复，以及1440×960和1024×680窗口；不向付费模型发送测试请求。

界面证据、结果与最新安装前数据保存在本轮备份目录。现场用户操作时序无法事后完整还原，修复针对已复现的视角/裁剪空白以及代码中确认的异步位置问题。
