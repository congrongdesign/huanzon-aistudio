# 模型配置简化改造方案

日期：2026-11-16
状态：产品与技术方案，尚未实施
适用应用：用户正在使用的 `/Applications/环中AIStudio.app` 及当前项目源码

## 1. 产品目标与边界

用户应能完成以下任务，而无需理解能力路由、绑定、协议端点和分类置信度：

1. 填入服务商提供的 API 地址与密钥，保存连接。
2. 找到需要的模型，加入日常使用的模型列表。
3. 在画布或对话中直接使用；失败时知道原因与下一步。

设计方向：沿用应用已有的字体、颜色与组件体系，以双栏管理页、短表单和按需展开的信息组织完成改造。重点是减少概念、减少持续占用空间的面板、让操作结果可理解。

本方案基于本机现有界面与源码审查，属于针对本产品的设计建议，不代表对外部产品当前版本逐一进行过实测。

不把所有功能塞进本次模型配置改造：去背景和文档转换等独立服务设置归属对应工具；不增加智能选路、负载均衡、跨服务自动重试和自动付费测试。

## 2. 现状与判断

| 现状 | 用户影响 | 处理原则 |
| --- | --- | --- |
| 左侧新增、最右侧填写 | 操作距离远，新增对象与输入位置脱节 | 新增、编辑统一使用独立弹窗 |
| 检测成功才允许保存 | 临时网络问题导致无法保存已填内容 | 保存与连接结果分离 |
| 草稿检测会修改当前连接 | 未保存操作影响正在使用的配置 | 草稿隔离，检测不改变正式选择 |
| 中转站列表、筛选侧栏、模型表格、配置抽屉同时展开 | 主区域狭窄，注意力分散 | 默认只保留连接列表和模型列表 |
| 默认表格六列合计 1206 像素 | 常见窗口中需要横向滚动 | 默认四列，详情按需展示 |
| 激活数混用模型数和能力绑定数 | 不同区域的数字难以理解 | 面向用户只统计去重后的模型连接 |
| 分类依据、置信度、原始字段常驻 | 用户被迫理解内部机制 | 移入模型详情的高级信息 |
| 填写密钥即显示绿色状态 | 容易误认为连接已经成功 | 连接状态与模型可调用状态分别表达 |
| 按模型类别推断计费方式 | 可能提供错误信息 | 无可靠来源时不显示确定价格或计费结论 |

## 3. 信息架构

主页面使用现有「模型」导航入口，页面标题为「模型配置」，不再同时堆叠模型广场、配置中心、激活管理等概念。

默认双栏：

- 左栏：全部常用模型、已连接服务列表、添加服务。
- 主区域：当前服务的模型，或跨服务的常用模型；顶部搜索、能力筛选和服务操作。

左栏服务条目展示名称和简短连接状态；选中后，主区域标题展示服务名称、简短地址、最近连接结果。条目的更多菜单提供编辑连接、刷新模型、移除连接。余额仅在服务支持时按需查询，不是主操作。

移除独立筛选侧栏和常驻配置抽屉。模型详情抽屉是临时覆盖层，关闭后恢复列表；常见窗口中不挤压主列表。

空页面只展示一段说明和「添加服务」按钮：填写服务提供的 API 地址和密钥，即可连接模型。提供 GRSAI、OpenAI 兼容、自定义等少量真实支持的模板；模板只帮助填写，不暗示官方合作或未经证实的兼容性。

## 4. 添加与编辑连接

### 4.1 表单

点击「添加服务」打开居中弹窗，首次焦点位于首个输入字段，支持 Tab、Enter 和 Escape。

默认只显示：

1. API 地址：模板可以预填；粘贴后清理首尾空格，检查 URL 格式。
2. API Key：远程服务按实际要求填写，本地服务允许无密钥；支持显隐。
3. 名称：根据模板或域名预填，用户可修改。

高级选项默认折叠，包含协议类型与必要的接口兼容设置。自动识别基于明确模板或已知规则，不反复盲试未知端点。保留用户原始输入，只在请求层按适配器生成正确地址，避免随意重复添加或删除 `/v1`。

主按钮「保存并连接」，次按钮「取消」。已有内容被修改后，误关闭时保留草稿或提示放弃；草稿不得进入模型选择器，也不能影响正式默认模型。

### 4.2 保存与连接流程

1. 执行本地字段校验；错误直接显示在对应字段下方。
2. 将有效配置写入正式存储。只有写入成功才能显示「已保存」。
3. 使用这一份配置快照进行连接检查并尝试获取模型列表，按钮展示进度并防止重复提交。
4. 成功后进入该服务模型列表，并提示「已连接，发现 N 个模型，选择常用模型即可使用」。
5. 失败时保留已保存配置和表单内容，在原位置说明原因，提供「重试」和「稍后设置」；不要求用户重新填写。

保存成功但连接失败的文案示例：「配置已保存，连接超时。请检查地址或网络后重试。」不能把它表达为保存失败。

获取模型列表失败不等于整个服务不可用。列表接口不受支持时允许手动添加模型 ID，状态显示「尚未验证」，不强制进行收费调用。

编辑密钥或地址后，旧检测结果失效。取消编辑不改变正式配置；正式保存也不应打断已经发出的生成任务。

### 4.3 状态表达

连接展示「未检测」「连接中」「已连接」「需要处理」，失败原因可以是认证失败、地址错误、超时或模型列表不受支持。显示检测时间，避免把历史结果当作实时保证。

模型展示独立状态：未验证、最近调用成功、最近调用失败；服务明确提供维护信息时显示维护中。拿到模型列表不能把所有模型标记为已验证。

## 5. 模型列表与常用模型

### 5.1 默认列表

默认表格只展示四列：

| 模型 | 用途 | 常用 | 操作 |
| --- | --- | --- | --- |
| 显示名称；次行可复制模型 ID | 生图 / 对话 / 视频等简短标签 | 开关 | 详情、设为默认等更多操作 |

维护或调用异常使用行内简短标记呈现，避免额外占一整列。正常状态不重复填满整表。

顶部只保留搜索、用途筛选和「仅看常用」。刷新模型、手动添加模型放在清晰的操作区。高级字段在详情内查看，不延续默认十四列的配置体系。

单服务列表不重复展示该服务来源；跨服务常用列表在模型名下展示服务名称，以区分同名模型。

### 5.2 常用开关的含义

「常用」只有一个清楚含义：打开后，模型出现在对应工作区的模型选择器里；关闭后从日常选择器移除，但保留服务配置和模型记录。

系统根据已知能力把模型放入对应选择器，不要求用户再激活、绑定或配置能力路由。无法可靠识别时标注「用途待确认」，让用户选择生图、对话或视频；不将猜测作为确定能力。

新增服务后不自动把几百个模型全部加入日常列表，也不替用户猜测最贵、最新的模型。可以展示少量基于明确规则的快速选择项，但需用户主动加入。

批量操作通过「批量管理」进入：此时才出现用于选择行的复选框和批量加入/移出常用操作。常用开关与批量复选框不混用。

### 5.3 默认模型

用户通过行内菜单设置对应用途的默认模型，并在该行显示「默认」标记。第一次仅加入一个适用模型时，可将其设为该用途默认，并给出简短提示；之后新增服务或刷新模型不改变既有默认值。

禁用或移除默认模型时，需要明确选择替代项或清空默认；有多个候选时不静默挑选。模型故障不自动跨服务切换，避免费用、隐私和结果不可预期。

### 5.4 模型详情

展示名称、模型 ID、来自哪个服务、已知用途、原始说明和最近调用结果。价格、分辨率、上下文等只在来源可靠时展示；没有数据时允许空缺。

「高级信息」中放分类依据、原始元数据和手动纠正用途。明确区分服务商声明、系统推测和用户设置。多用途模型可以确认多个实际支持的用途。

## 6. 能力路由和其他入口的去留

| 当前内容 | 改造后归属 |
| --- | --- |
| 能力路由页签 | 从模型配置中移除，底层必要的解析保留 |
| 已激活页签 | 合并为常用模型 |
| 去背景服务与专用模型 | 去背景工具内的服务设置，首次需要时再引导 |
| Codia 等转 PPT 任务接口 | 转换工具内的服务设置，不伪装成普通对话/生图模型 |
| 诊断页签 | 连接错误旁的「查看详情」，以及服务菜单内的连接检查 |
| 历史中转站下拉 | 不再默认展示，避免与已保存服务列表重复 |
| 余额查询 | 支持该能力的服务菜单或详情中按需提供 |
| 原始分类、Owner、端点等表格列 | 模型高级详情 |

用户已有的专用工具路由需要保留并迁移；不能为了移除入口直接删除底层数据，造成去背景或转换功能回退。

## 7. 工程实现

### 7.1 拆分边界

将模型配置从大型 `src/app/page.tsx` 中拆出，建议按职责建立：

- `ModelSettings`：双栏页面与导航。
- `ConnectionDialog`：新增、编辑和连接结果。
- `ConnectionList`：服务选择与更多操作。
- `ModelList`、`ModelDetails`：模型管理与详情。
- 独立配置存储、服务适配器和请求状态模块。

复用现有 shadcn/Radix、Tailwind 和图标体系，不为一次改造增加另一套 UI 框架。

### 7.2 数据和状态

区分四类数据：正式连接、编辑草稿、模型目录、用户常用与默认选择。连接检查结果独立存储，不再依赖多个字符串状态拼出是否可以保存。

模型连接以 `connectionId + modelId` 作为稳定身份；同一个模型的多个用途不重复计入模型数量。连接选择只改变当前浏览的列表，不能暗中改变各工作区已选模型。

本机正式存储是配置来源，前端缓存负责加速；写入错误需要反馈，不能仅更新 localStorage 就报告成功。迁移需要版本标记与幂等处理，避免多次启动产生重复连接或重置用户选择。

### 7.3 异步请求与任务

- 每次检测绑定连接 ID、配置版本和请求 ID，旧响应不得覆盖新输入或其他连接。
- 请求支持超时、取消与重复提交保护。
- 刷新模型失败时保留缓存，并说明更新时间。
- 目录刷新不自动删除常用选择；暂时消失的模型标记待确认。
- 每次生成任务捕获发起时的服务与模型配置快照，后续编辑不改变进行中任务。
- 不自动跨服务重试收费请求。

### 7.4 密钥处理

密钥默认遮挡，不放进提示文案、日志、截图和导出配置。适配器只把密钥发送到用户配置且明确支持的目标；重定向不得把密钥带往其他主机。现有存储迁移不增加密钥副本；系统钥匙串增强可作为独立后续工作，不阻塞交互改造。

## 8. 迁移与交付顺序

第一阶段交付完整核心闭环：双栏页面、连接弹窗、保存并连接、四列模型列表、常用与默认模型。同步移除旧主界面中的能力路由、激活和常驻诊断入口，并让专用工具的已有配置继续生效。

第二阶段完善高频边界：手动添加模型、错误定位、缓存刷新、批量管理、窄窗口、键盘操作，以及专用工具内的新用户配置引导。

第三阶段根据真实使用情况增加可选能力：服务支持的余额查询、明确来源的价格信息和更多服务模板。不先建设复杂的高级控制台。

旧数据映射：

- 现有服务档案保留 ID、名称、地址、密钥和模型缓存。
- 启用且显示在选择器中的能力绑定，按模型连接去重转为常用；各用途默认选择保持原值。
- 专用去背景和转换路由转到对应工具读取，保留原值。
- 用户手动分类保留，旧表格列宽不再约束新页面。
- 不清理真实项目、图片、字体或账号配置，不复制整套软件作为日常备份。

正式实施时以当前已安装应用的实际运行目录为交付目标，同步源码。更新前检查生成任务与未保存输入；正常重启先告知，存在不可安全中断任务时延后加载并明确说明。最终必须在真实桌面窗口验收后，才能报告已生效。

## 9. 验收标准

### 用户体验

- 目标：提供有效 API 地址和密钥后，首次用户两分钟内完成添加服务并加入一个模型；这是待验证目标，不是已取得结果。
- 新增流程只有一个主提交按钮，无需先检测再手动保存。
- 默认页面不出现能力路由、能力绑定和分类置信度等内部术语。
- 在 1280×800 窗口中，四列主列表和主要操作完整可见，无需横向滚动。
- 鼠标和键盘均可完成新增、修改、搜索、加入常用和查看错误；状态不能只靠颜色区分。

### 功能与数据

- 地址无效、错误密钥、超时、列表接口不支持、目录为空均有明确下一步。
- 连接失败后配置仍存在，保存写入失败则不会伪报成功。
- 检测草稿后取消，已有连接、默认模型和进行中任务保持原状。
- 快速切换服务、编辑地址和连续刷新时，无旧响应覆盖新状态。
- 常用模型数按模型连接去重，所有页面统计一致。
- 同名模型跨服务可区分，实际请求使用所选模型对应的服务配置。
- 迁移后原有常用模型、默认选择、去背景与转换服务继续可用；重复迁移不会重复创建。
- 保存、退出、重开应用后配置一致；刷新目录不清空用户选择。

### 工程验证

使用 pnpm 执行相关类型检查、构建及有意义的状态/迁移测试；针对持久化失败、竞态和迁移编写测试，不为简单样式变更堆积测试。

使用无损操作和模拟接口覆盖错误场景。真实服务默认只执行连接与目录查询；未获得明确授权不发起付费生成测试。若原生调用或特定服务尚未实测，交付时如实注明。

## 10. 推荐决策

采用「服务连接 + 常用模型」作为统一用户心智。复杂路由留在系统内部，专用服务设置回到对应工具。首先把添加、选择和排错做完整，再根据真实需求扩展高级能力。
