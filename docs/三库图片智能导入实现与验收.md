# 三库图片智能导入：本机首版实现与验收

2026-11-16。设计文件《三库图片智能导入功能设计.md》包含分阶段目标；本文件记录本次实际实现范围，避免将原型或后续目标当作已经交付。

## 已实现

- 提示词库、字体库、案例中心支持单张与批量图片导入，页面及指定分组支持拖入；详情的追加入口将多张图片保存为同一卡片附件，普通导入每图一张卡片。
- 统一直接入口支持静态 JPG/PNG/WebP，单张25 MiB、8000万像素。服务端按真实格式与解码结果校验。案例旧 AVIF/较大图片及 ZIP 保留兼容导入路径，该路径沿用旧交互。
- SQLite WAL 保存任务队列；原图复制、流式哈希、解码与512像素缩略图在 Node Worker Thread 中执行。桌面文件使用受控文件凭证，无法取得原生路径时回落到逐文件流式上传。
- 原图保存与AI分析独立调度；保存并发1、分析并发1，已有生成任务时暂缓新分析。完成原图保存后即可使用，切换工作区继续处理。
- 共用模型中心配置，AI一次分析产生名称、说明、标签、分类建议、OCR与复用提示词；无配置或限流时保留原图并进入等待。调用可能产生现有服务商的正常分析费用；不触发生图。
- 分类优先保留用户指定分组，否则匹配已有同名分类；不自动创建分组。提示词反推来源明确标注，不声称取得作者原始提示词。
- 哈希去重、分析缓存、重试登记幂等与分析提交幂等；手动修改过的字段受保护。
- 导入任务入口常驻，抽屉无阻断遮罩；暂停、继续、重试、停止后续分析与撤销本批新增。撤销保留已编辑或已使用内容；原有重复卡片不会因本批撤销被删除。
- 已保存队列在应用启动后的进度读取中恢复。尚未传完的浏览器 File 在刷新后需重新选择；原生文件任务需原路径仍可访问。追加附件仅保存，不重写已有卡片的分析内容。

## 当前边界与后续打包要求

- 本次未承诺1000张大图、低内存电脑、NAS断开或磁盘耗尽的完整性能SLA；百图测试使用小型合成图片，不代表25 MiB上限场景。
- 队列与重计算使用Worker Thread，业务卡片仍接入原有JSON存储；不是全库迁移SQL，也不是独立OS进程的故障隔离。
- 进度面板只显示最近300项、40批；更早任务仍可执行。全库搜索、分页与虚拟化继续沿用各库现有实现。
- 首版没有文件夹递归、剪贴板批量、逐字段证据评分或完整人工确认工作流。OCR置信度来自模型自报，复杂字形仍需人工核对。
- Windows安装包需同时携带 `workers/library-import-worker.cjs`、`@libsql/client`及目标系统/架构的libsql原生模块；不可把Mac arm64原生二进制当作Windows运行依赖。发布前用Windows真机验证队列创建、缩略图、恢复、原生拖入与升级数据保留。本次没有生成新的Windows发行包或完成Windows真机验收。
- 历史测试副本导致过度打包时，排除output等目录；保留其中项目归档与用户元数据。不要为每次本机更新创建整套应用备份。

## 拖入反馈补充

三库使用不占布局的虚线高亮层，显示“松开，导入到…”与目标库/分组；分组落点单独描边，追加按钮悬浮提示“松开，添加到此卡片”。反馈层 `pointer-events:none`，不遮挡真实落点；只对文件拖拽触发，退出区域、Esc、窗口失焦、drop/dragend清除提示。支持批量数量显示（浏览器在拖入阶段可提供数量时）。
