# 平台优化后续开发计划（v1.2 收敛版）

日期：2026-06-15  
范围：环中 AIStudio 主平台后续优化  
说明：基于 v1.1 整合版更新。当前深色模式已基本稳定，本版只聚焦剩余问题与后续收口，不重复转换中心、多模型对比等已明确不做的范围。

## 1. 当前判断

1. 深色模式主视觉已经基本干净，整体方向正确。
2. 目前深色模式的主要问题不是“风格错误”，而是对比还不够强、层次还不够清晰。
3. 浅色模式仍有少量残留颜色、局部控件风格不统一，是本轮重点。
4. 平台很多工作已经完成，后续不应再回头重做已稳定的底座。

## 2. 已完成 / 基本稳定

1. 深色模式的大方向已固定为黑白灰体系，发光感和明显蓝色偏置已明显减少。
2. 主要工作区、侧栏、弹层、按钮、下拉框等基础控件已进入统一底座。
3. 低价值入口已开始或已完成收敛。
4. 归档、回收站等核心数据链路已修正，不再按旧方式重复处理。
5. v1.1 中定义的统一规范已经可以继续复用，而不是每个页面各做一套。

## 3. 仍需优化的问题

### 3.1 浅色模式

1. 仍有少量残留颜色没有完全收干净。
2. 部分按钮、下拉框、标签、选中态、悬停态颜色不统一。
3. 背景、卡片、边框、浮层之间的层级还不够清爽。
4. 部分模块字号、字重、间距、图标识别性还不一致。
5. 少量地方还会出现“看着像有颜色，但又不是主色”的脏感。

### 3.2 深色模式

1. 主要问题已经不是风格错误，而是层次感还可再加强。
2. 某些面板、卡片、浮层之间的深浅关系还不够明显。
3. 少数区域仍偏灰，需要再压深一点或增强边界。
4. 局部控件的 hover、selected、disabled 状态还可以再清楚一些。

### 3.3 通用问题

1. 同类控件在不同模块里仍存在细微差异。
2. 下拉框、弹窗、tooltip、空状态、弱提示等浮层不够统一。
3. 小字、数字、禁用态的可读性需要整体再过一遍。
4. 新增页面如果不受约束，还是容易重新引入残留颜色。

## 4. 后续优化目标

1. 让浅色模式彻底干净，去掉残留色块和非必要强调色。
2. 让深色模式更有层次，但保持克制，不回到发光风格。
3. 统一所有基础控件的视觉规则。
4. 保证后续新增页面能直接沿用统一规范。

## 5. 优化顺序

| 阶段 | 目标 | 核心任务 | 结果 |
|---|---|---|---|
| P0 | 视觉收口 | 锁定主题 token 和控件规范，先做全局色彩审计 | 后续修改不再漂移 |
| P1 | 浅色模式清理 | 清理残留蓝紫色、统一背景/卡片/边框/浮层 | 浅色更干净 |
| P2 | 深色模式层次强化 | 略微加深背景，拉开层级，强化边界 | 深色更立体 |
| P3 | 跨模块一致性 | 统一图库、资产库、提示词库、PPT 工作台、画布 | 全站风格一致 |
| P4 | 回归保护 | 建立检查清单，避免再次引入残留颜色 | 后续维护更稳 |

## 6. 具体执行点

### 6.1 P0 视觉收口

1. 统一按钮、下拉框、标签、输入框、弹窗、hover、selected、focus、disabled 的基础规则。
2. 把现有主题里的残留颜色先列出来，再逐项清掉。
3. 明确浅色和深色各自的边界，避免互相污染。

### 6.2 P1 浅色模式清理

1. 清理所有残留蓝紫色和玻璃化效果。
2. 统一背景、卡片、边框、浮层的明暗层级。
3. 调整小字、数字、图标、选中态的识别性。
4. 统一不同模块的字号、行高、间距。

### 6.3 P2 深色模式层次强化

1. 让主背景、侧栏、卡片、浮层形成更清楚的三级层次。
2. 略微加深背景，减少发灰感。
3. 让按钮、选中态、禁用态、hover 更容易区分。
4. 保持无蓝色偏置、无霓虹感。

### 6.4 P3 跨模块一致性

1. 统一图库、资产库、提示词库、PPT 工作台、画布的控件风格。
2. 检查同一功能在不同页面中的表现是否一致。
3. 补齐边框、圆角、阴影、图标颜色、空状态等细节。

### 6.5 P4 回归保护

1. 新增 UI 前先过主题规范。
2. 修改前先检查是否会引入残留颜色。
3. 避免再出现“修一个地方，漏三个地方”的情况。

## 7. 验收标准

1. 浅色模式没有明显残留色彩。
2. 深色模式层次更清楚，但整体仍克制。
3. 同类控件在全站表现一致。
4. 不同模块之间没有明显风格断层。
5. 新增页面能够沿用现有规范，不再依赖临时补丁。

## 8. 不做范围

1. 转换中心主线不纳入这轮。
2. 多模型对比不做。
3. 不再回头重做已经稳定的深色基础框架。
4. 不以局部补丁方式继续堆视觉修复。

## 9. 结论

这轮后续优化的重点，不是继续大改，而是把剩余问题收干净：浅色模式先统一，深色模式再补层次，最后把跨模块一致性和回归规则固定下来。
