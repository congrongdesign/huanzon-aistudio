# 环中 AIStudio：Motif 全平台改造方案

版本：v2.0 · 2026-11-13 · 状态：仅方案

本方案将上一版输入与生成体验的规划扩展到整个现有平台。本轮核对当前源码、样式及 Motif 官方组件文档和部分注册表源码，没有修改业务代码、更新安装版或制作新预览。

## 1. 整体建议

采用 **Motif 的中性视觉与现成组件作为全平台共同基线**：白/灰与深灰表面、细边框、紧凑布局、克制圆角、清晰文字层级、少量有用途的动效。

适合的组件直接采用现有外观和交互细节，包括消息、附件、模型菜单、比例选择、清晰度、设置表单、轻量等待和图片对比。业务区域用这些组件组合，避免每个模块另外设计一套卡片、工具栏、输入框和弹窗。

成熟团队会先建立统一组件，再按模块接入，重点检查：

1. **视觉一致**：五个主工作区、弹层和后台任务都使用同一套表面、文字、间距和交互状态。
2. **业务语义正确**：设置未保存内容、模型服务来源、提示词分组、字体独立草稿和任务快照不因换组件丢失。
3. **操作持续可用**：多个任务运行时，输入、复制、下载和切换浏览仍能响应。
4. **性能有预算**：按需挂载、图像预览、局部更新和减少动态模式先落实，再接入装饰动效。

## 2. 当前平台范围与依据

当前主导航实际渲染的工作区为：**画布、提示词、字体、资产、模型**。另有项目侧栏、图片工具、操作历史、回收站、配置、归档/同步和导入等流程。

| 范围 | 当前实现依据 | 本次规划定位 |
| --- | --- | --- |
| 应用框架、项目、画布、对话、模型中心、资产、图片工具、设置/同步 | `src/app/page.tsx` | 平台主体，整体改造 |
| 主题与历史兼容样式 | `src/app/globals.css` | 建立统一基础，逐步消除冲突 |
| 提示词库与快速选择 | `src/components/PromptManager.tsx` | 保留一级分组，统一管理和插入体验 |
| 字体库、字体创作 | `FontLibrary.tsx`、`FontCreationWorkspace.tsx` | 与其他模块共用视觉组件，保持独立业务状态 |
| 案例中心、风格包 | `AssetCollectionsPanel.tsx` | 统一卡片、资料详情、编辑与复用 |
| 能力与操作路由 | `OperationRoutingPanel.tsx` | 与模型配置使用同一套表单行 |
| 归档与后台归档任务 | `ProjectArchiveCenter.tsx`、`BackgroundArchiveTasks.tsx` | 统一任务展示和长任务交互 |
| Pinterest 导入 | `PinterestImportDialog.tsx` | 统一选择、进度与结果反馈 |

源码中保留某个历史文件或状态类型，不代表其仍是当前导航功能。本次不恢复已经移除的独立图库、转换中心、技能库，也不按旧文档重新建设 PPT/Agent 工作区。资产中的“资产画廊”属于当前素材功能，继续优化其现有入口。

当前还有两处需要先理顺：

- 实际 CSS 已是中性配色：浅色主色为 `#2b3037`，深色背景为 `#111111`；旧 `UI_STYLE_GUIDELINES_V2.md` 仍描述紫色、玻璃化规范。实施时应更新为一份与真实组件一致的规范。
- `globals.css` 包含旧模块兼容映射和宽泛的样式覆盖。接入 Motif 前需确认它们不会把新组件的语义状态覆盖为同一种灰色，也不会使 Portal 弹层与页面主题不一致。

## 3. 哪些可以直接采用 Motif

“直接采用”指采用组件的现成布局、样式、选中态、键盘方式和适合的动效；中文文案、真实数据、事件和主题变量仍接本平台。它不表示把官网演示模型、价格、权限或计时器当作生产数据。

| Motif 组件 | 适用位置 | 推荐采用程度 | 必要边界 |
| --- | --- | --- | --- |
| **Settings Dialog / Section / Card / Row** | 应用设置、模型服务编辑、NAS/同步设置、能力路由表单 | 外观可完整采用；行/分区也能用于侧栏或全页 | 表单草稿放在面板外，切换分类不能因组件卸载丢失未保存内容 |
| **Message / MessageActions** | 所有创作对话 | 消息排布、气泡和操作显隐可完整采用 | 复制/插入等绑定原操作；键盘焦点和触屏也能访问 |
| **Attachment** | 上传参考图、对话附件、风格参考图、导入文件摘要 | 卡片、移除按钮、边框进度可完整采用 | 明确上传状态与引用身份，不把未上传图片当成可发送附件 |
| **Loading State** | 文字回复等待、列表加载、连接检测、索引与归档步骤 | 九点标记、一行状态、计时布局可完整采用 | 状态由真实任务驱动，计时局部更新 |
| **Model Menu / Model Select** | 对话模型、生图模型、能力路由的模型选择 | 菜单与列表样式可完整采用 | 模型绑定服务来源；仅显示实际支持的控制项 |
| **Provider Logo** | 模型列表和已知厂商标记 | 已知厂商图标可采用 | 中转服务不是模型厂商；未知来源使用中性图标，不冒充官方 |
| **Ratio Picker** | 生图参数、扩图比例预设 | 图形网格、选中反馈可完整采用 | 值来自对应模型/工具的可用比例 |
| **Resolution Picker** | 有离散清晰度选项的模型 | 分段外观和滑动选中态可完整采用 | 精确像素、质量与清晰度分别处理，保留现有自定义尺寸能力 |
| **Compare Slider** | 同构图的编辑前后、去背/高清结果对比 | 分隔线、拖动手柄、键盘操作可完整采用 | 输入图先对齐；不同构图/比例优先并排，避免错误对齐 |
| **Strength Slider** | 已有“严格/平衡/创意”等离散选项 | 轨道与分档反馈可采用 | 映射现有枚举；连续亮度/对比度滑杆继续使用数值滑杆 |
| **Date Range** | 已有按时间查看历史、收录、归档记录的筛选 | 日期面板、快捷范围、确认方式可采用 | 中文与时区统一；有真实日期字段才启用对应筛选 |
| **Gradient Cover** | 没有封面的项目、素材包或集合 | 固定 seed 封面可采用 | 真实作品有图优先显示真实图；不当作动态背景铺满页面 |

下列组件需调整后使用：

| 组件 | 用途 | 调整原因 |
| --- | --- | --- |
| Prompt Input | 普通画布和字体创作的共用输入外观 | 现有引用芯片、草稿恢复、输入法和字体风格结构需要适配；生图期间不全局切换为停止按钮 |
| Conversation | 对话滚动容器 | 接入现有消息、流式输出与滚动锚点，向上阅读后停止自动跟随 |
| Generation Overlay | 生图、局部重绘等可见占位卡 | 缩短官方约 1.4–1.6 秒的揭示过渡；限制动画数量；使用真实预览 URL 的加载/解码状态 |
| Tool Call / Agent Activity | 图片处理、导入、索引、归档的简洁任务摘要 | 只展示确实发生的步骤，不为普通生图虚构推理或工具执行过程 |
| Skill Detail | 案例、风格包、字体作品的资料详情 | 复用大图与信息区的布局思想；展示作品配方，保持作品完整可见，不复制技能/代码文件树 |
| Cover Fan | 空白画布的少量起步案例 | 可选项，只用于少量空状态卡片；主列表仍用规则网格，优先级低 |

Motif 没有提供完整的项目目录、提示词资产管理器、模型管理表格或无限画布引擎。这些区域采用现有 shadcn/Radix 基础组件，按 Motif 的边框、文字、间距、行样式和反馈方式统一。

## 4. 逐模块改造方案

### 4.1 全局导航与项目侧栏

**目标：进入任何模块，都能认出同一个平台。**

- 保持五个主要工作区，统一图标尺寸、按钮高度、选中背景、焦点和 Tooltip。导航不增加弹跳或长距离滑动效果。
- 当前导航存在 8px 标签，建议提升至可读的 10–11px；展开形态可用正常文字行，收起形态保留图标与提示。
- 项目列表统一为紧凑导航行：名称、置顶/运行状态、更多操作。重命名在行内完成，较少使用的导出、归档等放更多菜单。
- 没有作品缩略图的项目可以用 Gradient Cover 作小封面；不为封面另外发图片生成请求。
- 新建、搜索、列表与底部管理区的对齐关系一致；跨模块切换恢复各自滚动/筛选，不重置普通项目或字体草稿。

这一部分主要采用 Motif 的视觉规则与 Settings 的导航行语言，保留项目列表本身的行为。

### 4.2 普通画布与图片工具

**目标：给作品更多空间，让当前选择决定显示哪些工具。**

- 顶部保留项目、布局/视图、运行摘要及必要入口；模型与生图参数集中到输入框附近，避免顶部一排长下拉溢出。
- 选中图片出现统一浮动工具条：参考、下载、编辑与更多；多选时变为批量操作。少用的工具放统一菜单，已有功能保持可达。
- 裁剪、扩图、局部重绘采用相同的工具面板、参数行和确认/取消位置。扩图比例直接采用 Ratio Picker；已有离散保留强度可采用 Strength Slider。
- 固定工具条位置和尺寸，尽量不遮住图片主体；缩放/适应视图/整理画布归在视图工具区。
- 支持对齐的处理结果可提供 Compare Slider；扩图、换构图等无法严格对齐的结果继续完整预览或并排查看。
- 保留已有画布拖拽、框选、快捷键、视口裁剪和缩略图策略，任务动效不带动画布中的历史图片。

Motif 的 Flow Edge 适合有明确连接关系的节点编辑器；本轮不为装饰给普通图片之间加连线。

### 4.3 对话、输入与消息操作

**目标：输入、阅读和复用更直接。**

- 采用 Prompt Input 的统一框架：上方附件、中央输入、下方模型与参数/发送；采用 Attachment 原有样式。
- 采用 Message 的用户气泡与助手正文排布；复制、追加/替换输入、收录作品等操作在悬停或焦点时出现，触屏保留可发现入口。
- 普通回复用 Loading State；带任务的回复显示一行可展开的任务摘要，避免同时堆多个大状态框。
- 使用 Conversation 的有条件跟随；用户上翻时显示“回到最新”，保留文字选择和复制操作。
- 修复输入法 Enter、粘贴图片、长文本和引用身份；原有提示词分组快速选择器在输入框就近打开。
- 分清“追加到输入框”和“替换输入内容”，避免两个不同动作都叫“插入”；字体风格应用继续使用其独立替换语义。

普通/字体输入使用相同组件外观，草稿、会话和风格来源通过各自适配器绑定。

### 4.4 模型快捷选择与模型管理中心

**目标：创作时快速选，管理时看清真实配置。**

- 快捷选择采用 Model Menu / Model Select 的现成样式，支持搜索、常用/最近、当前选中与键盘导航。
- 同名模型来自两个服务时显示两条独立记录，保存 `providerId + modelId`，任务快照保持原路由。
- 模型中心保留当前的服务列表、模型表格、启用/常用与能力路由；统一搜索、筛选、行高、列标题、状态徽标和空结果样式。
- 模型表格适合密集管理，不全部换成大卡片；批量操作只在有选择时出现。
- 服务商、能力、操作路由、诊断使用 SettingsSection/Card/Row，减少一层层套边框与重复标题。
- 目录刷新、连接检测和余额查询各自显示状态；正在检测一个服务不锁住全部配置。
- 不显示未经接口或配置证实的速度、费用、能力与思考强度。

### 4.5 提示词库与快捷选择器

**目标：保留分组，把管理和调用做轻。**

- 保留一级分组；“全部、未分组、自定义分组”使用统一导航行或紧凑分组栏。组多时搜索或横向滚动，不增加多级分类。
- 顶部统一为搜索、新建提示词和必要的分组管理；默认不让大段新增表单长期占据列表上方，点击新建再展开编辑。
- 提示词以紧凑文本列表/轻卡片展示，长内容默认折叠摘要，打开后可读全文。插入动作保持醒目，删除/移动归入明确操作区。
- 快捷选择器采用与模型菜单相同的搜索和键盘语言：搜索 → 分组筛选 → 选择 → 返回输入。保留提示词实际项目范围，不在视觉改造中迁移数据归属。
- 删除分组后提示词归入未分组的语义保持；删除单条优先给可行的撤销反馈。

Motif 没有独立提示词库组件；这里复用其列表、表单和弹层语言，不恢复原子词/组合包/模板/版本等已精简层级。

### 4.6 资产库、NAS/本地素材与检索

**目标：图片是主体，目录和详情为查找与使用服务。**

- 保留目录/素材包、中央网格、详情的现有组织；统一头部搜索、筛选、排序与视图切换。窄窗口时详情区收起为抽屉，避免挤压成极窄三栏。
- 资产卡片以真实缩略图和名称为主，来源/标签放次级行；悬停或选择后露出引用、加入画布、更多操作，避免每张卡常驻多排按钮。
- NAS、本地与飞书等来源配置使用 Settings 的分区和表单行；长路径显示省略与复制入口，操作错误定位到对应来源。
- 加载、索引运行、离线来源、无匹配结果与空素材包分别呈现；索引任务采用 Loading State / Activity 的简洁摘要。
- 分页/按需加载保留，使用适合网格尺寸的预览。选择和滚动不重复请求原图。
- “素材库/索引检索”与“案例/风格”属于不同层面的切换，视觉上区分为数据视图与内容分类，减少同时出现的同级分段按钮。

### 4.7 案例中心与风格包

**目标：先看到效果，再理解和复用配方。**

- 卡片统一为封面、名称、一行描述和当前使用状态，选中详情后再显示完整提示词、参考图与来源。
- 详情借鉴 Skill Detail 的大图与信息工作区：完整作品预览、可复用提示词、参考图、原参数与主要使用动作。
- 字体/设计成品以 `contain` 完整显示，不能照搬 Skill Detail 的满幅裁切使字被截断；封面缩略图和原图预览分开。
- 没有参考图、缺少原始资料、正在保存/上传等状态使用统一附件与错误反馈。现有案例导入流程复用进度摘要。
- 用风格、追加描述、仅引用图片分别表达作用；切换不改写已提交任务。

这里只复用 Skill Detail 的布局组件与视觉，不创建技能库、技能执行或代码文件树。

### 4.8 字体库与独立字体创作

**目标：字体体验与全平台一致，内容保持独立。**

- 字体卡片、分组、搜索、收录表单和详情采用与资产/案例一致的组件；原提示词、补充参考图、缺失资料提示清楚分区。
- “用此风格”进入字体独立创作，当前风格以独立卡片显示；个人要求在输入框中。更换风格只替换风格包，保留个人要求和个人参考图。
- 创作输入、模型选择、参数、生成卡片和任务摘要复用普通画布的通用组件；通过字体会话适配器绑定现有保存、撤销和任务快照。
- 资产区的“字体案例”和左侧字体入口使用同一数据及动作定义，防止同一张卡在不同入口表现不同。
- 字体仍全局共用，结果只有在明确导出时进入普通项目。

### 4.9 设置、归档、同步与导入

**目标：表单简洁，长任务不中断创作。**

- 通用配置直接采用 Settings Dialog 的左分类、右表单和轻淡入；窄窗按组件原有方式变为顶部横向分类。
- 使用统一的 SettingsSection/Card/Row：标签、说明、控制项在同一列对齐；保存反馈、字段错误和按钮位置一致。
- 模型服务以模型中心为唯一维护来源，其他设置给跳转入口，避免留下两份同类表单互相覆盖。
- Motif 默认只挂载当前设置页。这里由外层保存各分类草稿与 dirty 状态，切换页面不会丢掉 API Key、路径或其他未保存编辑；不采用“离开分类即丢弃”的默认结果。
- NAS 归档、同步和 Pinterest 导入统一为：选来源/目标 → 任务摘要 → 后台执行 → 查看结果。实际步骤与已有流程一致，关闭详情后后台任务继续。
- 上传/归档已知字节数、处理已知文件数时可展示真实进度；只有粗粒度状态时使用等待标记和已完成数量。
- 失败项目可查看原因并针对性重试；明确区分重查任务、重传文件和重新生成，保持已有幂等规则。
- 图片展示失败、某个来源离线等局部问题只影响对应卡片/来源，不弹阻塞全平台的大错误框。

### 4.10 操作历史、回收站、看图与通用反馈

- 操作历史统一为时间、动作、状态的一行摘要，展开才显示参数和失败详情；有可对齐的前后图时采用 Compare Slider。
- 回收站沿用现有恢复/删除能力，统一列表、选择、空状态和反馈，避免误把回收站物品展示为可直接参考的正常作品。
- 看图保持完整图像、缩放、方向键和下载；外围工具条、Tooltip、图标和退出方式采用共同组件语言。
- 统一短暂 Toast、字段错误、卡片错误和页面错误四个层级。成功提示不重复刷屏；无网络、空数据与无搜索结果使用不同文案。
- 登录/账号等低频流程统一输入、按钮、错误和焦点样式；品牌入口可保留自己的封面，不影响工作区的统一。

## 5. 全平台共同样式规则

| 维度 | 方案 |
| --- | --- |
| 色彩 | 以 Motif 的中性色和组件语义为主；红/绿/琥珀只在有实际状态含义时使用；作品图片保留自己的色彩 |
| 表面 | 画布底、侧栏/面板、卡片/输入、弹层四层；以细边界和少量明度差区分，减少层层玻璃、发光与重阴影 |
| 字体 | 保留系统中文字体；常规内容 12–14px，辅助文字 11–12px，少用 8–10px 文字承担关键操作 |
| 间距 | 统一 4/8px 节奏，区块常用 16/24px；相同性质的表单和列表共用列对齐 |
| 圆角 | 优先采用 Motif 组件原有尺度；同类输入、卡片、弹层一致，不让每个面板独立调一套数值 |
| 选择 | 使用轻背景、勾选/边框与文字共同表达；主要提交按钮与普通选中项区分 |
| 动效 | 悬停/按下约 100–150ms，菜单/切换约 140–240ms，新结果短淡入约 200–320ms；交互不等待退出动画完成 |
| 键盘与触屏 | 焦点始终可见，Esc 关闭就近浮层并还原焦点，菜单支持方向键，触屏可找到操作入口 |
| 主题 | 页面与独立 Portal 都使用同一 token；明暗模式不依赖宽泛颜色替换维持可读性 |

优先完整保留 Motif 现有设计细节，只在真实业务语义、中文可读性和性能限制需要时改动。

## 6. 接入方式与性能底线

### 6.1 一套组件，两层接入

建议将采用的原始组件放在 `components/ui/motif/`，业务组合放在独立目录，便于保留来源、更新和定位差异。

```text
ui/motif/                  采用的 Motif 展示组件
platform/                  通用导航行、列表工具栏、表单与反馈组合
creation/                  输入框、模型参数、任务卡与图片展示
各模块适配器                项目/提示词/资产/字体/模型/归档各自的数据与事件
```

同一服务、模型、图片、分组、任务沿用现有稳定 ID。不能通过重新挂载整个工作区来刷新一个选中态，也不能让共享组件把不同模块的草稿合并。

### 6.2 依赖与样式核对

项目已具备 React 19、Radix/shadcn、cmdk、lucide、date-fns 和 react-day-picker，大部分基础组件能够衔接。

已核对部分官方注册表：Message 不新增外部 UI 依赖；Compare Slider 使用已有 lucide；Strength Slider 用 CSS 动效；Date Range 依赖的基础库已存在。Settings Dialog 依赖 `motion`，Skill Detail 还声明了 `motion` 与聚合 `radix-ui`；当前项目使用分包 Radix，实施前应决定按官方依赖接入或做等效导入适配，不能盲目全量安装覆盖现有 UI 文件。

Prompt Input 的富文本路径需要单独评估编辑器依赖与旧草稿转换。完整采用它的外观，不要求把原有数据协议一并替换。

实际复制源码时核验许可证，保留版权声明和来源说明。本轮只读取文档/源码，没有安装这些依赖。

### 6.3 性能与真实状态

- 延续当前四路生图队列、请求幂等、批量轮询、画布视口裁剪和预览图逻辑。先增加可复用展示订阅，不另外建立第二套任务系统。
- 任务等待阶段有依据才命名。当前按等待秒数推算的“排队/绘制/处理”等文案需改成真实状态或诚实的“正在处理”。
- 把服务端任务状态与浏览器图片传输/解码状态分开；缓存图片直接显示，图片加载重试不再次调用计费生成。
- 图多时按可见区域加载，不给每张历史卡片加流动背景；窗口隐藏或减少动态模式下停用装饰动画。
- 输入、搜索、计时和单任务更新保持局部；设置面板按需挂载，草稿放外层；大目录保留分页或虚拟化选择。
- 输入回显 p95 ≤50ms、常用菜单可交互 ≤100ms、关键交互 INP <200ms 可作为初始目标，需在实施时用同机基线验证。它们是目标，尚无本轮生产性能实测。

## 7. 推荐实施顺序

| 阶段 | 内容 | 为什么先做 |
| --- | --- | --- |
| 1：全局基础 | 对齐真实 token/规范，通用按钮/菜单/Tooltip/弹窗/表单行，导航和项目行 | 一次建立规范，让后续所有模块一致，避免新旧样式互相覆盖 |
| 2：最高频创作 | 普通画布输入、消息、模型参数、图片工具条、生成状态、结果出现与对话滚动 | 使用最频繁，直接影响创作效率和等待体验 |
| 3：整理与复用 | 提示词分组、资产网格/详情、案例与风格包、字体库/字体创作 | 共用列表、附件、详情和创作组件，统一调用入口 |
| 4：配置与后台流程 | 模型管理表格与路由、设置、索引、归档/同步/导入、历史与回收站 | 覆盖其余流程并收敛旧表单，完成全平台一致性 |
| 5：整体回归与本地交付 | 明暗主题、窄栏、输入法、并行任务、大数据量、备份与可回退安装 | 确保展示改造不会破坏已用顺手的业务与保存机制 |

每阶段形成可审阅的实际模块，不一次性重写整份 `page.tsx`。高频输入和生成的既有详细约束继续参考上一版《Motif交互改造方案》，全平台范围与视觉方向以本文为准。

## 8. 验收方式

实施后至少覆盖以下场景，本轮尚未执行这些生产回归：

1. 五个主工作区、独立弹层和看图工具在明暗主题下风格一致，文字可读、选中态清楚；窄聊天栏与窄窗口不截断主操作。
2. 设置分类来回切换后未保存值仍在；保存与取消有明确作用；关闭/重新打开的草稿语义一致。
3. 同名不同服务模型可区分；模型、参数、参考图身份及任务快照没有被样式迁移改变。
4. 中文输入法、换行、复制粘贴、参考图插入/删除与旧草稿恢复通过；菜单可完全用键盘操作。
5. 两组任务并行、合计四路运行时仍可输入、下载旧图和复制旧消息；上翻历史不被自动滚动打断。
6. 500/1000 张历史图、长模型目录、较多资产与提示词分组分别测试；记录冷热缓存、长任务、输入延迟和渲染范围。
7. 上传失败、图片解码失败、服务超时、短时断网分别给对应动作；重连与图片重载不重复创建计费任务。
8. 字体全局共用、独立创作和风格替换规则通过；普通/字体草稿互不覆盖；提示词一级分组保留。
9. 已精简入口保持精简；卡片与表单没有因照搬组件而引入技能文件树、审批流、统计面板等新层级。
10. 所有实际采用组件保留来源与许可证；完成类型、Lint、构建及相关既有业务测试，再更新本地安装版。
