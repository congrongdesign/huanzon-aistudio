# 平台优化开发计划

版本：v1.3  
日期：2026-06-14  
适用范围：环中AIStudio 全平台优化开发，不包含转换中心

---

## 1. 目标

把当前平台从“功能较多、界面割裂、维护成本高”升级为“视觉统一、核心流程稳定、资产可复用、编辑可回退、后续易维护”的生产型平台。

---

## 2. 现状判断

当前平台主要问题集中在五类：

1. **视觉不统一**
   - 深色模式里蓝色残留多。
   - 浅色模式也有不少按钮、边框、下拉框和交互细节需要继续优化。
   - 深色模式整体偏灰、偏脏，对比度还不够明确，需要再压深一点。
   - 按钮、下拉框、选中态、边框、弹窗风格不一致。
   - 同类组件在不同模块里字号、间距、层级不统一。

2. **功能入口偏散**
   - 主导航内容较多。
   - 一些模块重复、重叠或使用价值不高。
   - 用户进入核心任务的路径不够短。

3. **编辑底座不稳**
   - 画布选区、局部重绘、预览、提交、回退还需要继续打磨。
   - 选区和最终提交容易出现不一致。

4. **资产复用不足**
   - 图库、参考库、灵感库能存，但还不够“可检索、可复用、可回填”。

5. **提示词回流链路不完整**
   - 画布里的图片和提示词库之间没有直接闭环。
   - 需要能从图片直接读取提示词，并一键入库，减少重复整理。
   - 提示词资产和画布素材之间需要建立来源关联，方便回查和复用。

6. **结构维护成本高**
   - `src/app/page.tsx` 过大。
   - `PPTWorkshop.tsx`、`PromptManager.tsx` 也偏大。
   - 继续在大文件里补丁式修复，会越来越难。

---

## 3. 总原则

1. 先统一，再扩展。
2. 先减法，再加法。
3. 先稳定主流程，再做增强功能。
4. 所有新功能必须接入统一的视觉、状态、历史、错误体系。
5. 不再围绕低价值模块继续堆功能。

---

## 4. 总体策略

### 4.1 先做 P0

优先修复：

1. 全站 UI 统一。
2. 功能减法与入口收敛。

### 4.2 再做 P1

重点提升：

1. 画布编辑底座。
2. 资产系统。
3. PPT 工作台。

### 4.3 最后做 P2

用于长期维护：

1. 提示词与知识资产收口。
2. 代码结构重构。

---

## 5. 分阶段开发计划

## Phase 0：基线收敛与风险控制

### 目标

先把后续开发的底层约束定住，避免继续新增问题。

### 任务

1. 统一视觉规范入口。
2. 梳理仍在使用的模块和页面。
3. 标记重复入口、低价值入口、未来待移除入口。
4. 统一修复清单，避免边修边漏。

### 产出

1. 平台模块清单。
2. 优先级清单。
3. 风格统一规则。
4. 需要收敛/删除的功能清单。

### 验收

1. 后续开发有明确顺序。
2. 不会一边做新功能一边反复改旧规则。

---

## Phase 1：全站 UI 统一

### 目标

把平台的视觉语言统一成一套黑白灰主导、层级清晰、识别性稳定的界面，同时把浅色模式和深色模式都调整到更耐看、更统一的状态。

### 任务拆分

#### 1.1 统一主题基线

1. 清理全站蓝色、紫色、霓虹感残留。
2. 统一浅色和深色模式的语义 token。
3. 统一页面底色、卡片、浮层、输入框、按钮、边框、阴影。
4. 统一选中态、hover、focus、disabled 的表现。
5. 深色模式整体再加深一点，减少发灰发脏的感觉，拉高层级对比。
6. 浅色模式同步优化按钮、边框、下拉框、弹窗和选中态的识别性与克制感。

#### 1.2 统一组件风格

1. 按钮统一：
   - 主按钮
   - 次按钮
   - 幽灵按钮
   - 危险按钮
   - 禁用按钮
2. 下拉框统一：
   - 高度
   - 字号
   - 边框
   - 选中态
3. 弹窗统一：
   - 遮罩
   - 浮层背景
   - 边框
   - 阴影
4. 标签统一：
   - 状态标签
   - 筛选标签
   - 数量标签

#### 1.3 统一模块视觉

重点模块：

1. 主画布
2. 项目栏
3. 图库
4. 资产库
5. 提示词面板
6. PPT 工作台
7. 批量模块
8. Node Workflow

#### 1.4 双主题交互细节

1. 浅色模式下统一按钮尺寸、留白、hover 和按下态，避免视觉发虚。
2. 深色模式下统一高亮、禁用、选中边框和文本颜色，避免局部发蓝或发灰。
3. 下拉框、切换按钮、标签、弹窗在两套主题下都保持一致的层级和节奏。
4. 页面切换、面板展开、浮层出现等交互保持轻量、顺滑，不做过度装饰。

### 交付物

1. 全站统一的视觉规则。
2. 核心组件样式基线。
3. 深色模式一次性整改结果。
4. 浅色模式统一优化结果。

### 验收标准

1. 深色模式不再出现明显蓝色残留。
2. 同类控件在不同模块表现一致。
3. 下拉框、按钮、选中态在浅色和深色都清晰。
4. 低字号文字可读。
5. 深色模式不再偏灰、偏脏，层级和对比更明确。
6. 浅色模式的交互细节和识别性同步改善。
7. 所有悬停、选中、禁用、弹窗、下拉框状态统一。

---

## Phase 2：功能减法与入口收敛

### 目标

减少用户决策成本，让核心功能更快触达。

### 任务拆分

#### 2.1 收敛主导航

1. 只保留高频主入口。
2. 低频入口降级为二级页或配置项。
3. 去掉重复概念相近的模式入口。

#### 2.2 合并重叠功能

1. 合并重复的批量相关能力。
2. 收敛工作台里重叠的操作入口。
3. 减少相同操作在不同面板里出现多次。

#### 2.3 清理低价值模块

优先继续评估：

1. 访客模式
2. agent 模式
3. 飞书同步相关入口
4. 过度分散的独立配置入口
5. 侧边栏和顶部残留的重复入口

### 交付物

1. 主导航重排方案。
2. 功能合并方案。
3. 已移除/隐藏功能列表。

### 验收标准

1. 用户进入核心任务的路径更短。
2. 页面内重复入口明显减少。
3. 低价值功能不再干扰主流程。
4. 相关入口在 UI 上彻底收口，不再出现多个同义按钮。

---

## Phase 3：画布编辑底座

### 目标

让画布成为稳定的“可选、可涂、可改、可回退”的编辑底座。

### 任务拆分

#### 3.1 智能选区稳定化

1. 点击选中小元素更稳定。
2. 框选后可继续微调。
3. 补涂路径始终可用。
4. 预览 mask 和提交 mask 保持一致。

#### 3.2 局部重绘链路统一

1. 选区结果统一生成 effective mask。
2. 不再出现预览和提交不一致。
3. 失败后可回退到上一步。

#### 3.3 历史与撤回

1. 统一历史记录入口。
2. 统一撤回逻辑。
3. 统一局部编辑操作记录。

### 交付物

1. 选区稳定版。
2. 局部重绘稳定版。
3. 历史与回退统一版。

### 验收标准

1. 点击、框选、补涂都能稳定工作。
2. 预览和最终结果一致。
3. 回退链路可靠。

---

## Phase 4：资产系统升级

### 目标

把图库从“存储工具”升级成“可复用资产中心”。

### 任务拆分

#### 4.1 统一图库体验

1. 图库、参考库、灵感库浏览逻辑统一。
2. 卡片样式统一。
3. 筛选栏和详情栏统一。

#### 4.2 增强检索能力

1. 标签检索。
2. 相似图检索。
3. 风格检索。
4. 更明确的项目归属。

#### 4.3 增强复用能力

1. 一键回填到画布。
2. 一键引用到提示词，并支持从画布图片直接读取提示词后入库。
3. 一键送入 PPT 工作台。

#### 4.4 归档与回收站重构

1. 归档图库和回收站的列表、筛选、详情、操作入口统一。
2. 修复归档图库新建文件夹流程的交互和状态问题。
3. 修复回收站恢复、永久删除、清空回收站等操作的异常。
4. 补齐作品库到归档的交互入口，不能只依赖画布侧操作。
5. 优化画布归档流程，避免“先选中再归档”导致图片被误移动。
6. 归档操作应支持从卡片直接触发，不要求用户先右键再点二次按钮。
7. 归档成功后要明确反馈位置变化，避免图片状态和实际位置不一致。
8. 归档图片必须和原图文件生命周期解耦，避免归档后被回收站误删。

### 交付物

1. 统一资产浏览体验。
2. 资产复用闭环。
3. 更强的资产检索路径。
4. 更稳定的归档/回收站操作链路。

### 验收标准

1. 用户能更快找到可用素材。
2. 资产能直接进入下一步任务。
3. 不同图库不再像不同产品。
4. 归档图库、新建文件夹、回收站操作都稳定可用。
5. 作品库和画布都能有明确、顺手的归档入口。
6. 归档图片与回收站不再共享同一份文件。

---

## Phase 5：PPT 工作台稳定化

### 目标

保持 PPT 工作台作为平台里最强的生产模块之一。

### 任务拆分

#### 5.1 稳定任务流

1. 优化任务状态。
2. 优化刷新恢复。
3. 优化失败重试。

#### 5.2 优化审核效率

1. 更快看到结果。
2. 更顺的重生入口。
3. 更清晰的待审核、失败、已通过状态。

#### 5.3 优化导出链路

1. 导出更稳定。
2. 失败提示更明确。
3. 导出后结果可追踪。

### 交付物

1. 更稳的工作台流程。
2. 更少打断的批量任务。
3. 更清晰的审核页面。

### 验收标准

1. 批量任务更稳定。
2. 生成结果更快可见。
3. 审核和导出更顺。

---

## Phase 6：提示词与知识资产收口

### 目标

让提示词和知识资产更容易管理和调用。

### 任务拆分

#### 6.1 简化页面结构

1. 合并重复的管理入口。
2. 保留核心能力：
   - 分类
   - 模板
   - 版本
   - 测试
   - 快速插入
   - 来源追踪
3. 控制页面层级，让常用操作在一屏内完成。

#### 6.2 画布提示词回流

1. 在画布图片详情、右键菜单、工具栏里提供“读取提示词”“加入提示词库”。
2. 读取来源按优先级处理：
   - 图片自身已保存的提示词
   - 生成记录里的提示词
   - 聊天记录里的提示词
   - 手工补录的提示词
3. 支持一键进入入库面板，默认带出图片来源、项目、模型、比例、时间。
4. 入库前可继续编辑提示词内容、标题、分类、标签、备注。
5. 支持重复提示词检测，避免同一内容反复入库。
6. 支持把同一张图片生成的多条提示词统一归档，便于对比和复用。
7. 画布上的图片卡片、详情面板、消息引用图都应该能进入同一条回流链路。

#### 6.3 提示词沉淀与复用

1. 减少重复管理入口。
2. 让提示词能更自然地回流到画布和工作台。
3. 让提示词能从画布直接沉淀到提示词库，并可再次回填到画布、工作台和对话输入。

### 验收标准

1. 页面层级更少。
2. 常用功能更快到达。
3. 不再被复杂管理流程干扰。
4. 画布里的图片可以直接读取提示词并一键入库。
5. 新入库提示词带有明确来源，后续可以回查到原图。
6. 提示词可以继续回填到画布、工作台和对话输入。
7. 读提示词和入库动作在所有相关入口表现一致。

## Phase 7：代码结构重构

### 目标

降低长期维护成本，让后续优化更容易做。

### 任务拆分

1. 拆分 `src/app/page.tsx` 中的大块逻辑。
2. 将通用样式和控件规则抽公共层。
3. 拆分 `PPTWorkshop.tsx` 的高耦合段落。
4. 拆分 `PromptManager.tsx` 的复杂区域。
5. 统一 feature module 的组织方式。

### 建议拆分方向

1. 主题与视觉层
2. 主导航层
3. 画布层
4. 图库层
5. 资产层
6. 提示词层
7. 工作台层

### 验收标准

1. 大文件规模下降。
2. 修改单个模块不会牵连太多地方。
3. 后续修 UI 不再到处补洞。

---

## 9. 风险与对策

### 风险 1：继续补丁式修复

对策：

1. 先定统一规则。
2. 再批量替换。
3. 不允许每个模块单独发明样式。

### 风险 2：功能太多导致收敛不彻底

对策：

1. 每次新增功能前先判断是否可合并。
2. 低价值功能优先隐藏而不是继续扩展。

### 风险 3：大文件继续膨胀

对策：

1. 优先做结构重构。
2. 新功能必须走 feature module。

### 风险 4：画布编辑再次失灵

对策：

1. 统一选区和提交中间层。
2. 统一历史和回退机制。

---

## 10. 最终结论

这次优化的重点不是“继续加功能”，而是把平台做成一套更统一、更稳、更容易维护的产品系统。

最优先顺序：

1. 统一 UI
2. 减少入口
3. 稳定画布
4. 强化资产
5. 稳住 PPT
6. 收口提示词，并打通画布提示词入库
7. 重构代码
