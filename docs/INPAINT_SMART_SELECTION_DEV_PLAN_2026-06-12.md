# 智能选区重构开发文档（融合版）

更新时间：2026-06-12  
适用范围：`局部重绘 / 智能选区` 功能链路（`src/app/page.tsx` + `src/app/api/inpaint/route.ts`）

---

## 1. 背景与目标

结合已有阶段文档（`AI_DESIGN_PLATFORM_FRONTIER_REPORT_2026-06-12.md`、`EDITABLE_PPT_LAYERING_OPTIMIZATION_PLAN_2026-06-12.md`、`EDITABLE_PPT_LAYERING_GITHUB_RESEARCH_2026-06-12.md`）和当前实现，智能选区目标统一为：

1. 不依赖“模式切换”也能完成高效编辑。
2. 点击可选中小元素，框选可批量选中，选区边界稳定可预览。
3. 选区结果直接生成像素级 mask，不再走稀疏点阵笔刷。
4. 失败时可自然降级到手工补涂，但不打断主流程。

---

## 2. 当前问题复盘（本轮故障）

用户反馈：`无法画笔涂抹 + 无法选中`。  
对应根因：

1. 交互状态耦合过深：`smart mask`、`strokes`、`elementMap` 同时作为“唯一真值”，互相覆盖。
2. 入口锁死：强制智能态后，手工涂抹路径被短路。
3. 坐标映射不一致：`idMap` 与画布显示尺寸缩放映射在部分路径不统一，导致命中偏移。
4. 选区渲染与提交路径不一致：预览看似选中，但提交时不是同一份 mask。

结论：需要先做“交互与数据层解耦”，再谈算法精度。

## 4. 新的功能定义（不做模式切换）

### 4.1 交互规范（单一工作流）

1. 默认：点击元素选中（单选）。
2. `Shift/Ctrl/Cmd + 点击`：多选/取消单个元素。
3. 拖拽：框选元素集合。
4. `按住修饰键并拖拽`：手工补涂（加/减）到当前智能 mask。  
   - 建议：`Ctrl/Cmd` 为加，`Alt` 为减。
5. “智能选区”按钮：刷新候选元素与基础 mask，不切换模式。

### 4.2 可视反馈

1. 悬停透明覆盖。
2. 选中区域蚂蚁线（优先真实轮廓，最小可用为 bbox）。
3. 当前提交 mask 覆盖预览（与最终请求同源）。

---

## 5. 技术架构重构

### 5.1 前端状态解耦（核心）

新增三层 mask 概念，避免互相覆盖：

1. `baseSmartMask`：自动选区产物。
2. `manualDeltaMask`：手工加减涂抹差量。
3. `effectiveMask`：提交前合成结果（唯一提交来源）。

原则：`strokes` 仅用于绘制输入，不再作为选区真值。

### 5.2 提交链路统一

1. 所有路径最终都生成 `effectiveMaskBase64`。
2. `confirmInpaint` 只读取 `effectiveMaskBase64`。
3. 禁止在提交时重新“猜测”选区（例如把元素再采样成点阵）。

### 5.3 坐标系统一

所有命中和绘制都使用同一转换函数：

1. `canvas display -> internal canvas`
2. `internal canvas -> idMap space`
3. `internal canvas -> original image space`

转换函数集中维护，禁止在各事件里手写缩放逻辑。

## 6. 后端算法路线（从可用到高质量）

### 6.1 当前可用层

1. 前景/背景估计 + 连通域。
2. 边缘感知超像素细分（已落地原型）。

### 6.2 近期增强（无需大模型）

1. 小区域保留策略（按局部对比度和边缘强度保留微元素）。
2. 邻域一致性与形态学后处理（减少锯齿、孤岛噪点）。
3. 候选评分：`area / edge / color contrast / stability`，用于点击候选排序。

### 6.3 中期增强（模型侧）

1. Sidecar 接入 SAM2（点击/框提示 refine）。
2. 文本指令选区：Grounding DINO -> SAM2 refine。
3. 无 sidecar 时自动回退到本地 CV 管线。

---

## 7. 接口约束（统一协议）

### 7.1 `PUT /api/inpaint`（选区分析）

返回至少包含：

1. `maskBase64`
2. `idMap`（与 `width/height` 对齐）
3. `elements[]`（`id/area/coverage/bbox/score`）
4. `stats`（`elementCount/threshold/subjectRatio`）

### 7.2 `POST /api/inpaint`（执行重绘）

输入只认最终 `maskBase64`，不接受“元素 id 列表”替代提交。

---

## 8. 验收标准（从“好用”倒推）

### 8.1 功能可用性

1. 点击选中成功率：> 85%（典型海报页，20 次点击统计）。
2. 小元素（图标/字牌/灯笼）可单独选中，不被整块吞并。
3. 框选后可继续点选微调，选区不会被覆盖。
4. 手工补涂始终可用，不依赖模式切换。

### 8.2 性能

1. 选区分析耗时：1080p 图在本机 < 1200ms（不含网络下载）。
2. 交互帧率：拖拽/悬停预览稳定 45fps+。

### 8.3 稳定性

1. 预览选区与提交结果一致（抽样对比误差 < 1px 映射级）。
2. 任意失败可回退到上一版本，不污染原图。

## 9. 本周执行清单（先恢复再优化）

### P0（立即修复，1-2 天）

1. 恢复手工补涂路径（不依赖模式切换）。
2. 统一 `effectiveMask` 提交链路，移除点阵中间态。
3. 修正点击/框选坐标映射，保证 `idMap` 命中一致。
4. 增加前端调试开关：显示 `idMap` 命中点与最终 mask 轮廓。

### P1（质量提升，2-4 天）

1. 候选元素评分与小元素保留策略。
2. 选区边缘平滑与蚂蚁线轮廓绘制。
3. 加入交互回归测试用例（点击、框选、补涂、提交一致性）。

### P2（能力增强，1-2 周）

1. SAM2 sidecar 最小接入。
2. 语义选区（文本描述选中对象）。

## 10. 测试用例（最小集）

1. 单击小图标，只有该图标被选中。
2. 单击人物头部，不应吞并整个人物与背景。
3. 框选一片区域后，继续 Shift 点选微调。
4. 选区后按住修饰键补涂，提交结果与预览一致。
5. 清空后再次“智能选区”，状态不脏。
6. 断网/接口失败时仍可手工补涂并提交。
